# 구체 구현 배제

[Git It iOS 컨벤션 공통 원칙](./README.md)의 규칙 문서입니다.

컨벤션·아키텍처·패키지 규칙은 **모든 구현에 공통으로 적용되는 절대적인 기준만** 다룹니다.
특정 타입·컴포넌트·target의 목록이나 인터페이스는 코드가 바뀔 때마다 함께 낡고, 규칙과
현황을 한 문서에 섞어 어느 쪽이 정본인지 흐리게 합니다.

## 다루지 않는 것

- 현재 코드에 있는 특정 타입·컴포넌트·target·프로토콜을 나열한 표나 목록
  (분류표, 배치표, 존치 목록, target 구성표, 파일·타입 수 같은 수치)
- 특정 타입의 인터페이스, 메서드 목록, 연관값 구성 같은 정의
- 특정 명세·브랜치·커밋의 적용 결과와 그때 확정한 동작 차이
- 규칙을 특정 타입 이름에 묶는 서술("`X`를 쓴다", "`Y`가 그 예다")

## 대신 쓰는 것

- **규칙은 책임과 역할로 서술합니다.** 특정 컴포넌트 이름 대신 그 컴포넌트가 맡는 책임
  (화면 루트 컨테이너, 순차 흐름 스택, 공용 텍스트 컴포넌트 등)을 씁니다.
- **예시는 중립 이름을 씁니다.** `Example`, `<흐름>`, `<화면>`, `<기능>`처럼 실제 코드와
  겹치지 않는 이름과 자리표시자로 규칙의 형태만 보여 줍니다.
- 다음은 규칙의 어휘이므로 그대로 씁니다: 컨벤션이 정한 중첩 타입·폴더·접미어 어휘
  (`State`, `Action`, `Constant`, `Style`, `Binding`, `DisplayModel`, `Controls/` 등),
  패키지 이름, 표준 라이브러리·Apple 프레임워크·외부 라이브러리의 타입.
- 현재 구현의 목록과 판정 결과가 필요하면 코드 검색이나 도구로 확인하고, 설계 경위는
  기능 명세(`specs/`)와 Spec Kit 기록(`docs/spec-kit/`)에 남깁니다.
