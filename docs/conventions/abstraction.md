# Git It iOS 추상화 컨벤션

**상태**: 초안

**작성일**: 2026-09-16

## 목적

이 문서는 프로젝트가 소유한 타입에 프로토콜을 둘지 판단할 때 사용합니다. 프로토콜은
구현을 바꿀 여지를 열어 두는 대신 파일 하나와 주입 배관을 늘립니다. 그 대가를 치를
근거가 무엇인지 미리 정해 두어, 계층 관례만으로 추상화가 늘어나는 것을 막습니다.

문서 우선순위, 문서 구조와 문서 간 참조 규칙은
[컨벤션 공통 원칙](common/README.md)이 소유합니다. 패키지의 책임과 허용 의존 방향은
[아키텍처](../architecture.md)가, 공개 이름의 어휘는
[네이밍 컨벤션](./naming.md)이 소유합니다.

## 1. 적용 범위

프로젝트가 선언을 소유하는 모든 프로토콜에 적용합니다.

- Domain·Data·Infrastructure가 정의하는 계약
- Composition이 조립 대상으로 받는 타입
- Feature·App·UI가 정의하는 내부 프로토콜

다음은 이 문서가 다루지 않습니다.

- 표준 라이브러리와 외부 패키지가 정의한 프로토콜의 채택 (`Sendable`, `Equatable`,
  `Codable`, TCA의 `Reducer` 등)
- `associatedtype`이나 제네릭 제약을 표현하기 위한 프로토콜 — 타입 시스템이 요구하는
  형태이며 교체 가능성과 무관합니다
- 프로토콜이 아닌 추상화(상속, 클로저 주입, 제네릭 파라미터)의 선택 기준

## 4. 검토 체크리스트

- [ ] 새로 추가한 프로토콜이 [두 가지 근거](./abstraction/protocol-criteria.md) 중
      하나에 해당하는가?
- [ ] 테스트 더블을 만들기 위해 프로토콜을 추가하지 않았는가?
- [ ] 더블이 필요한 의존을 그 타입이 의존하는 경계 계약으로 내렸는가?
- [ ] 구현이 하나뿐인 프로토콜을 남겼다면, 교체 지점이 프로덕션에 실재하는가?

      존치 근거 목록을 함께 갱신했는가?

## 문서 변경 기준

프로토콜을 두는 근거가 바뀌거나 새 근거를 추가할 때 수정합니다. 특정 패키지에만
적용되는 예외는 이 문서가 아니라 해당 패키지 규칙 문서에서 관리합니다.
