# rename과 설계·동작 변경 분리

[Git It iOS 네이밍 컨벤션](../naming.md)의 규칙 문서입니다.

rename은 기존 책임과 동작을 유지한 채 식별자와 그 참조를 바꾸는 변경입니다. 다음 중 하나라도 함께 바뀌면 순수 rename으로 보지 않습니다.

- 프로토콜의 연산 집합 또는 타입의 상태
- 저장 위치, 값의 수명과 소유자
- 비동기·오류·취소 동작
- 패키지 책임 또는 의존 방향
- 외부 API·schema와의 mapping 또는 호환성

순수 rename은 선언, 모든 참조, 테스트 이름과 관련 문서를 같은 범위에서 일관되게 갱신하고 기존 동작을 검증합니다. 설계·동작 변경도 필요하면 네이밍
변경과 별도의 명세·계획·작업으로 나누고 각각의 변경 이유, 영향과 검증 범위를 구분합니다. 이름을 먼저 바꿀지 설계를 먼저 바꿀지는 의존 관계에 따라
결정하되, 한 변경에서 두 결과를 구분할 수 없게 섞지 않습니다.

대규모 공개 API rename은 이름이 더 짧거나 통일돼 보인다는 이유만으로 수행하지 않습니다. 호출부, Adapter, 테스트, 문서, 외부 호환성과 진행
중인 명세에 미치는 영향을 먼저 확인하고 책임 불일치가 근거로 확인된 범위만 변경합니다.
