# 모델과 DTO

[Git It iOS 네이밍 컨벤션](../naming.md)의 규칙 문서입니다.

- Domain 모델은 비즈니스 의미와 상태를 표현하며 서버 schema, 플랫폼 타입이나 저장 기술을 이름에 노출하지 않습니다.
- Data 모델은 데이터 처리 책임과 수명을 표현합니다. 저장 모델은 저장 이후에도 무엇을 보존하는지 식별할 수 있어야 합니다.
- 외부 요청·응답 형식을 표현하는 DTO는 경계 역할이 실제로 DTO일 때 `DTO`를 사용할 수 있습니다. Domain 모델에 표면적 통일을 위해 `DTO`를 붙이지 않습니다.
- `Request`, `Response`, `Stored`, `Cached` 같은 수식어는 방향 또는 수명이 모델의 의미를 실제로 구분할 때만 사용합니다.
- 하나의 모델 이름으로 외부 계약, 저장 모델과 Domain 모델을 동시에 표현하지 않습니다. Adapter에서 각 경계가 소유하는 모델로 변환합니다.
