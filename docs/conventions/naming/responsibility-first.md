# 실제 책임을 먼저 설명합니다

[Git It iOS 네이밍 컨벤션](../naming.md)의 규칙 문서입니다.

이름을 정하기 전에 선언의 책임을 한 문장으로 설명합니다. 후보 이름의 각 단어는 그 책임, 구분해야 할 경계 또는 값의 수명을 설명해야 합니다. 선언이 맡지
않는 저장 방식, 공급자 내부 개념, 실행 환경이나 미래 책임을 이름에 넣지 않습니다.

예를 들어 어떤 계약의 책임이 "로그인 세션을 시작하고 복원하며 종료한다"라면 로그인 세션 문맥은 책임을 구분하는 근거가 됩니다. 반대로 실제
authorization 상태를 다루지 않는 저장 계약에 `Authorization`을 붙이는 것은 저장 값의 내부 형태를 계약 책임으로 오인하게 할 수
있습니다.
