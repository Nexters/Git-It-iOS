# 축약과 약어

[Git It iOS 네이밍 컨벤션](../naming.md)의 규칙 문서입니다.

- 축약형이 원래 용어보다 책임과 범위를 불명확하게 만들면 사용하지 않습니다.
- 동일 경계의 독자가 일반적으로 원형을 복원할 수 있고 오해 가능성이 낮은 표준 약어만 사용합니다.
- Apple 플랫폼과 Swift 생태계가 고정한 `URL`, `HTTP`, `ID` 같은 표기는 해당 의미를 그대로 사용할 때 유지할 수 있습니다.
- 표준 약어는 전부 대문자로 쓰고(`repositoryURL`, `projectID`), 식별자의 첫 단어일 때만
  전부 소문자로 낮춥니다(`urlString`, `idToken`). `Url`, `Id`, `Http`처럼 첫 글자만 대문자인
  절충 표기는 사용하지 않습니다.
- `DTO`는 Data의 외부 전송 모델 역할을 구분할 때 사용할 수 있지만, 모든 모델에 붙이는 공통 접미어가 아닙니다.
- 기능 이름을 임의로 줄인 접두어는 같은 글자가 다른 개념을 뜻하거나 검색 가능성을 낮출 수 있으므로 사용 근거가 없다면 전체 용어를 사용합니다.

한 파일이나 target 안에서만 통하는 축약은 공개 API의 근거가 되지 않습니다. 새 약어가 필요하면 사용처, 원형, 충돌 가능성과 경계 밖 가독성을
리뷰에서 설명할 수 있어야 합니다.
