# App Store 긴급 심사 요청

Apple의 **Expedited App Review Request**에 제출할 내용과 그 근거를 정리합니다.
대상은 Git-It 최초 출시 빌드이며, 요청 사유는 **2026-09-09(KST) NEXTERS 데모데이**라는
고정된 공개 발표 일정입니다.

## 제출 전 전제

| 전제 | 이유 |
| --- | --- |
| 앱이 이미 심사에 제출되어 있어야 한다 | 긴급 심사는 **대기열 순서를 앞당기는 요청**이라 심사 대상 빌드가 없으면 접수되지 않습니다. App Store Connect에서 1.0.0(빌드 7) 제출을 먼저 끝내세요 |
| 요청은 Account Holder 또는 Admin 계정으로 한다 | 폼이 로그인한 Apple Developer 계정 기준으로 앱을 식별합니다 |
| 요청 횟수를 아낀다 | Apple은 계정당 승인 건수를 제한합니다. 이번 요청이 소진되면 다음 릴리스에서 쓸 수 없습니다 |

제출 경로는 <https://developer.apple.com/contact/app-store/?topic=expedite> 입니다.

## 붙여넣을 요청문 (영문)

```text
App Name: Git-It
App Apple ID: 6793460413
Version: 1.0.0 (Build 7)
Bundle ID: com.nexters.hytime.gitit

REQUEST
We respectfully request an expedited review for the initial release of Git-It.

REASON - FIXED PUBLIC LAUNCH DATE
Git-It is scheduled to be presented at a public demo event on September 9, 2026 at
9:00 AM KST (UTC+9). Our team demonstrates the app on stage, and attendees are directed
to its App Store page. The date was set by the event organizers and cannot be moved. We
submitted the build on <<제출 일시>>. Under the standard queue the app will not be live
in time for the event, which is the only reason we are asking.

WHAT THE APP DOES
Git-It turns a public GitHub repository into a personalized quiz set, so developers can
review what they have actually built. All quiz content is generated by AI from the
source repository.

REVIEW SUPPORT
Complete reviewer instructions, including a public repository URL to test with, are in
the App Review Information notes. Two points worth highlighting:
- The app uses Sign in with Apple exclusively, so no demo credentials are needed.
- Quiz generation intentionally takes at least 5 minutes. The progress screen staying
  visible for that long is expected behavior, not a hang.

This is our only expedited review request. Thank you for considering it.
```

남은 자리는 `<<제출 일시>>` 하나이며, 나머지는 그대로 씁니다.
주최 단체명과 행사 공지 링크는 요청문에 넣지 않기로 했습니다. 그만큼 "고정된 일정"이라는
주장을 Apple이 외부에서 확인할 수 없으므로, 되물어 올 경우에 대비해 행사 일정을 증명할
자료를 준비해 두세요.

## 작성 원칙

| 원칙 | 이유 |
| --- | --- |
| 날짜를 구체적으로 쓴다 | "곧", "이번 주" 같은 표현은 검증할 수 없어 사유로 취급되지 않습니다 |
| 일정이 **우리 통제 밖에서 이미 고정**되었음을 밝힌다 | 자체적으로 정한 출시일은 긴급 사유로 인정되지 않습니다 |
| 심사 편의를 함께 제시한다 | 순서를 앞당겨도 2.1(App Completeness)로 리젝되면 의미가 없습니다 |
| 감정 호소와 사업적 손해를 쓰지 않는다 | 마케팅 예산·매출 손실만 근거로 들면 거절되는 유형입니다 |
| 한 번만 요청한다 | 재촉 메일은 승인률을 떨어뜨립니다 |

## 알고 있어야 할 리스크

- **긴급 심사는 통과를 보장하지 않습니다.** 순서만 앞당깁니다. 리젝되면 수정 후 다시
  대기열에 들어가며, 남은 48시간으로는 두 번째 사이클을 감당하기 어렵습니다.
- **최소 5분 대기가 가장 큰 리젝 위험입니다.**
  ([GenerationWaitPolicy.swift:18](../../sources/Projects/Domain/LearningProject/Models/LearningProject/GenerationWaitPolicy.swift#L18)의
  `minimumWait: 300`) [심사 노트](app-store-review-notes.md)의 해당 문단을 반드시 채워
  제출하세요.
- **AI 생성 콘텐츠 신고 경로가 없습니다.** 지침 1.2로 문의가 오면 즉시 대응할 수 없으므로,
  [심사 노트의 마지막 절](app-store-review-notes.md)에 적힌 한계를 알고 있어야 합니다.
- **업로드한 빌드 7이 제출하려는 커밋을 담고 있는지 확인하세요.** 아카이브 시점 이후
  커밋이 쌓이면 저장소 상태와 심사 대상 빌드가 어긋납니다.

## Plan B — 심사가 제때 끝나지 않을 때

1. **TestFlight 외부 테스트 링크로 시연합니다.** 베타 앱 심사는 App Store 심사와 별도
   대기열이고 일반적으로 더 빠릅니다. 데모데이 전에 외부 테스트 그룹과 공개 링크를
   미리 만들어 두세요.
2. 발표는 실기기 로컬 빌드로 진행하고, App Store 링크는 승인 후 공지 채널로 공유합니다.

두 경로 모두 데모데이 전날까지 준비해 두면 심사 결과와 무관하게 발표가 가능합니다.

## 제출 전 확인 목록

- [ ] App Store Connect에서 1.0.0(빌드 7) 제출을 끝내고 상태가 `Waiting for Review`다
- [ ] [심사 노트](app-store-review-notes.md)의 `<<...>>` 자리를 실제 값으로 채웠다
- [ ] 위 요청문의 Apple ID·제출 일시·행사 URL을 채웠다
- [ ] 넣은 저장소 URL로 생성이 끝까지 성공하는 것을 직접 확인했다
- [ ] 개인정보 처리방침·이용약관 URL이 열린다
      ([policy-manifest.json](../../sources/Projects/App/GitIt/Resources/Policies/policy-manifest.json))
- [ ] TestFlight 외부 테스트 링크를 Plan B로 준비했다
