# 기능 명세: Figma UI 레이아웃 상수 검증

**Git-flow 유형**: `feature`

**기능 브랜치**: `미생성 (예정: feature/figma-layout-audit)`

**생성일**: 2026-08-19

**상태**: 초안

**입력**: 사용자 설명: "Figma 파일을 기준으로 컴포넌트와 View의 값을 점검하고, 명확한 상수값 체크리스트를 작성한 뒤 체크리스트 기반 UI 테스트를 TDD로 수행한다."

## 변경 시나리오와 테스트 *(필수)*

### 시나리오 1 - Figma 레이아웃 계약 확인 (우선순위: P1)

UI 개발자는 Figma의 `사용한 컴포넌트` 영역과 현재 `UIComponent` 구현을 대조해 각 변형의 크기, 간격, 여백, 모서리와 터치 영역을 하나의 검증 가능한 체크리스트에서 확인한다.

**주요 행위자**: UI 개발자와 디자이너

**우선순위 이유**: 기준값이 확정되지 않으면 자동화 테스트와 레이아웃 수정의 기대 결과를 판정할 수 없다.

**독립 테스트**: 체크리스트의 모든 항목이 Figma 근거, 적용 컴포넌트·변형, 목표값, 허용 오차와 현재 상태를 포함하는지 문서 검토로 확인한다.

**수용 시나리오**:

1. **전제** Figma에 동일 컴포넌트의 여러 크기·상태 변형이 존재할 때, **실행** 개발자가 체크리스트를 확인하면, **결과** 각 변형의 목표 레이아웃 값과 현재 대응 여부를 서로 혼동하지 않고 식별할 수 있다.
2. **전제** Figma에는 있지만 아직 코드 계약이 없는 변형이 있을 때, **실행** 체크리스트를 검토하면, **결과** 미대응 상태와 검증 보류 사유가 명시된다.
3. **전제** Figma 커넥터에서 속성값을 직접 조회할 수 없는 항목이 있을 때, **실행** 체크리스트를 검토하면, **결과** 화면 실측값과 기존 저장소 근거가 구분되고 추정값은 확정값으로 기록되지 않는다.

---

### 시나리오 2 - 레이아웃 회귀를 자동 검출 (우선순위: P2)

UI 개발자는 체크리스트의 고정값을 자동화 UI 검증으로 실행해 컴포넌트 크기나 배치가 기준을 벗어나면 구현 수정 전에 실패 결과를 확인한다.

**주요 행위자**: UI 개발자와 CI 운영자

**우선순위 이유**: 문서만으로는 이후 변경에서 동일한 레이아웃 회귀가 재발하는 것을 막을 수 없다.

**독립 테스트**: 대표 변형별 자동화 UI 검증을 실행해 의도적으로 기준과 다른 현재 구현은 실패하고, 기준과 일치하는 구현은 통과하는지 확인한다.

**수용 시나리오**:

1. **전제** 목표값과 다른 컴포넌트 변형이 렌더링될 때, **실행** 레이아웃 UI 검증을 실행하면, **결과** 컴포넌트 이름·변형·기대값·실제값을 포함해 실패한다.
2. **전제** 모든 대상 변형이 목표값과 허용 오차 안에서 렌더링될 때, **실행** 같은 검증을 실행하면, **결과** 대상 항목이 모두 통과한다.
3. **전제** Dynamic Type 또는 기기 폭에 따라 콘텐츠 크기가 변할 때, **실행** 검증을 실행하면, **결과** 고정 시각 표면과 적응형 콘텐츠 영역을 구분해 잘못된 고정 프레임을 강제하지 않는다.

---

### 시나리오 3 - 불일치 레이아웃 교정 (우선순위: P3)

UI 개발자는 실패하는 검증을 기준으로 레이아웃 상수와 변형 계약을 수정하고, 기존 접근성 의미와 공개 생성 경로를 유지한 채 전체 검증을 통과시킨다.

**주요 행위자**: UI 개발자와 앱 사용자

**우선순위 이유**: 자동 검출된 불일치를 실제 렌더링에 반영해야 디자인과 앱 사이의 차이가 해소된다.

**독립 테스트**: 수정 전 실패 증거와 수정 후 동일 테스트의 성공 결과를 비교하고 기존 UI·디자인 시스템 테스트가 계속 통과하는지 확인한다.

**수용 시나리오**:

1. **전제** 일반 버튼과 Liquid Glass 아이콘 버튼의 크기 변형이 Figma와 다를 때, **실행** 구현을 교정하면, **결과** `LG 54pt`, `SM 40pt`, `MD 40pt`, `SM 36pt`의 해당 계약이 허용 오차 안에서 렌더링된다.
2. **전제** 카드·행·헤더·시트·탭 골격의 고정 레이아웃 값이 체크리스트와 다를 때, **실행** 구현을 교정하면, **결과** 각 대상 변형의 자동화 검증이 통과한다.
3. **전제** 레이아웃 교정이 완료되었을 때, **실행** VoiceOver 의미와 최소 터치 영역을 검증하면, **결과** 기존 접근성 라벨·trait가 유지되고 상호작용 대상은 최소 44pt를 충족한다.

---

### 예외·경계 사례

- 텍스트가 길거나 Dynamic Type이 커져 콘텐츠 높이가 증가해도 체크리스트의 고정값이 텍스트 잘림을 유발해서는 안 된다.
- 기기 폭이 목표 Figma 프레임과 다르면 화면 전체 폭이 아니라 컴포넌트 자체의 고정 표면과 시스템 여백만 비교한다.
- 비활성·누름·오류 상태는 시각 상태가 달라도 같은 크기 변형 안에서는 외곽 크기가 바뀌지 않아야 한다.
- Figma에 대응 항목이 없는 `StyledText`, `ResourceImage`, 검토 전용 View는 Figma 고정값 비교 대상에서 제외하되 기존 검증이 깨지지 않아야 한다.
- Figma 속성 원본을 조회하지 못하고 화면 실측만 가능한 값은 허용 오차와 근거 수준을 명시하고, 정확한 속성값처럼 단정하지 않는다.
- 시스템 `TabView`, Button, Dynamic Type처럼 플랫폼이 소유하는 적응형 값은 임의의 픽셀 상수로 고정하지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 Figma에 대응하는 현재 구현 컴포넌트와 모든 지원 변형을 식별해야 한다.
- **FR-002**: 시스템은 각 대상 변형의 크기, 간격, 여백, 모서리, 터치 영역 중 적용되는 고정값을 체크리스트로 제공해야 한다.
- **FR-003**: 각 체크리스트 항목은 Figma 근거 위치, 목표값, 허용 오차, 현재 구현 경로와 검증 상태를 포함해야 한다.
- **FR-004**: Figma 직접 속성값, 화면 실측값, 기존 저장소 문서값을 서로 다른 근거 수준으로 구분해야 한다.
- **FR-005**: 일반 버튼은 Figma에서 확인된 `LG 54pt`, `SM 40pt` 높이 변형을 독립적으로 표현하고 검증할 수 있어야 한다.
- **FR-006**: Liquid Glass 아이콘 버튼은 Figma에서 확인된 `MD 40pt`, `SM 36pt` 외곽 크기 변형을 독립적으로 표현하고 검증할 수 있어야 한다.
- **FR-007**: 자동화 UI 검증은 구현보다 먼저 추가되어 현재 불일치에 대한 실패 증거를 제공해야 한다.
- **FR-008**: 자동화 UI 검증은 실패 시 컴포넌트, 변형, 기대값과 실제값을 식별할 수 있어야 한다.
- **FR-009**: 레이아웃 교정은 기존 공개 생성 경로, 디자인 토큰 사용, 접근성 라벨과 선택 trait를 보존해야 한다.
- **FR-010**: 상호작용 가능한 요소는 시각 표면 크기와 별개로 최소 `44pt × 44pt` 터치 영역을 유지해야 한다.
- **FR-011**: 고정값 검증은 `0.5pt`의 기본 허용 오차를 사용하되, 화면 실측 근거만 있는 항목은 체크리스트에 별도 오차를 명시해야 한다.
- **FR-012**: Figma에 대응하지 않거나 플랫폼 적응형인 값은 고정값 검증 대상에서 제외하고 제외 근거를 기록해야 한다.
- **FR-013**: 대상 컴포넌트의 레이아웃 검증과 기존 `DesignSystemTests`, `UIComponentTests`가 함께 통과해야 한다.

### 핵심 엔터티

- **레이아웃 계약 항목**: Figma 컴포넌트·변형, 목표 속성, 목표값, 단위, 허용 오차, 근거 수준과 구현 경로를 연결한다.
- **렌더링 측정 결과**: 컴포넌트·변형별 기대값, 실제값, 차이와 통과 여부를 나타낸다.
- **검증 대상 변형**: 동일 컴포넌트에서 크기·상태·스타일 조합을 식별하고 어떤 값이 공유되거나 달라지는지 나타낸다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: Figma 대응이 확인된 구현 컴포넌트와 지원 변형의 100%가 체크리스트에서 추적된다.
- **SC-002**: 체크리스트의 모든 고정값 항목이 근거 수준, 목표값, 허용 오차와 자동화 검증 식별자를 가진다.
- **SC-003**: 확인된 불일치마다 수정 전 최소 1회의 실패 결과와 수정 후 동일 검증의 성공 결과가 남는다.
- **SC-004**: 최종 렌더링 측정값의 100%가 항목별 허용 오차 안에 들어온다.
- **SC-005**: 대상 상호작용 요소의 100%가 최소 `44pt × 44pt` 터치 영역과 기존 접근성 의미를 유지한다.
- **SC-006**: 관련 UI 테스트와 기존 디자인 시스템 회귀 테스트가 모두 통과한다.

## 가정

- Figma 파일의 `사용한 컴포넌트` 영역과 `docs/ui-component-checklist.md`가 이번 점검 대상 목록의 공동 근거다.
- 이번 범위는 이미 코드 대응이 있다고 표시된 Figma 컴포넌트와 그 지원 변형이며, 체크리스트에서 미구현으로 표시된 신규 컴포넌트 구현은 제외한다.
- Figma 화면을 100% 확대해 확인한 일반 버튼과 Liquid Glass 아이콘 버튼의 크기값은 이번 기능의 확정 입력으로 사용한다.
- Figma 커넥터 호출 한도로 직접 속성 조회가 불가능한 나머지 항목은 기존 저장소의 Figma 실측 문서와 브라우저 화면 실측을 사용하며 근거 수준을 명시한다.
- 플랫폼이 제공하는 적응형 레이아웃과 Dynamic Type 동작은 픽셀 동일성보다 잘림 방지와 의미 보존을 우선한다.
