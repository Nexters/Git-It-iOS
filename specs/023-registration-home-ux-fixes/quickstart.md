# 검증 가이드: 등록 흐름·홈 화면 UX 결함 해소

**입력**: [spec.md](./spec.md), [plan.md](./plan.md) | **날짜**: 2026-09-01

구현이 명세를 충족하는지 확인하는 실행 절차다. 각 절차는 명세의 시나리오·성공 기준에
직접 대응한다. 구현 코드는 담지 않는다.

## 사전 준비

```sh
make init
```

이미 초기화했다면 workspace만 다시 만든다.

```sh
make tuist
```

> 공유 확장 target을 추가한 뒤에는 `tuist generate`를 반드시 다시 실행해야 한다. manifest만
> 바꾸고 재생성하지 않으면 확장이 빌드 대상에 들어오지 않는다.

## 자동 검증

```sh
project_build_runner=$(./tools/repository-paths/bin/repository-paths.sh GIT_IT_PROJECT_BUILD_RUNNER)
```

세 명령은 `sources/DerivedData/PreCommit`을 공유하므로 순차 실행한다.

```sh
"$project_build_runner" build
```

```sh
"$project_build_runner" compile
```

```sh
"$project_build_runner" test
```

기대 결과: 전 scheme Debug 빌드 성공, 전 테스트 통과(SC-011).

### 단위 검증으로 확인하는 항목

| 대상 | 확인 내용 | 대응 |
| --- | --- | --- |
| `HomeCardScrollLayoutTests` | 기준 위치에서 각도 0, 스크롤 위치별 각도 연속성 | FR-021~023, SC-007 |
| `HomeFeature` 테스트 | 진행 중 입력 수신 시 등록 진입 차단, 해제 시 복귀 | FR-005~009, SC-003 |
| `ProjectRegistrationFeature` 테스트 | `readyDate` 전 결과 도착 시 전이 보류, 이후 즉시 전이 | FR-012, FR-013 |
| `ProjectRegistrationFeature` 테스트 | 초기값이 있으면 `task`에서 검증 1회 자동 시작, 빈 값이면 시작하지 않음, 두 번째 `task`는 무시 | FR-025a |
| `GenerationWaitPolicy` 테스트 | `readyDate`가 `requestedAt + 300초` | FR-011 |
| 진행 상태 저장소 테스트 | 저장·복원·해제, 상한 초과 시 만료 | FR-005, FR-008 |
| 알림 클라이언트 테스트 | 예약·취소·중복 예약 시 1건 유지 | FR-010, FR-014 |

시간에 의존하는 검증은 짧은 `GenerationWaitPolicy`와 고정 `now`를 주입해 수행한다. 실제
300초를 기다리지 않는다.

## 수동 검증

시뮬레이터에서 앱을 실행해 확인한다. 시나리오 번호는 [spec.md](./spec.md)를 따른다.

### 시나리오 1 — 링크 입력 키보드 (FR-001~004)

1. 홈에서 "지금 불러오기"를 눌러 링크 입력 화면을 연다.
2. 하단 "다음" 버튼의 화면 내 위치를 기억한 뒤 링크 필드를 탭한다.
   - **기대**: 키보드가 올라와도 버튼 위치가 변하지 않는다(SC-001).
3. 제목 영역, 안내 패널 여백, 하단 여백을 각각 터치한다.
   - **기대**: 매번 키보드가 닫히고 입력한 텍스트는 남는다(SC-002).
4. 키보드가 올라온 상태에서 "불러오기 방법"을 탭한다.
   - **기대**: 키보드가 닫히고 패널이 펼쳐진다.
5. 키보드가 올라온 상태에서 입력 지우기 버튼을 탭한다.
   - **기대**: 입력이 지워지는 기존 동작이 수행된다.

### 시나리오 2·3 — 진행 중 표시와 알림 타이밍 (FR-005~016)

> 300초를 실제로 기다리지 않으려면 `GenerationWaitPolicy`를 짧은 값으로 주입한 디버그
> 구성으로 확인한다. 최종 확인은 기본값으로 1회 수행한다.

1. 레포지토리를 등록해 생성을 요청하고 진행 화면에 머문다.
   - **기대**: 결과가 먼저 도착해도 진행 화면이 완료로 전이하지 않는다.
   - **기대**: 진행률이 먼저 끝나면 마지막 단계가 진행 중으로 유지된다.
2. 대기 시간이 지난다.
   - **기대**: 진행 화면 완료 전이, 완료 알림 도착, 홈 진행 중 표시 해제가 함께
     일어난다(SC-009).
3. 다시 등록을 요청하고 "홈에서 기다리기"로 홈에 복귀한다.
   - **기대**: 불러오기 버튼이 "문제 생성 중" 비활성 표기로 바뀐다.
   - **기대**: 버튼을 눌러도 등록 화면이 열리지 않는다(SC-003).
4. 결과 도착 전에 앱을 백그라운드로 보내거나 종료한다.
   - **기대**: 예정 시각에 알림이 도착한다(SC-004).
5. 생성이 진행 중인 상태에서 앱을 완전히 종료하고 다시 실행한다.
   - **기대**: 불러오기 패널이 진행 중 표기로 복원되고 남은 대기가 이어진다(SC-010).
6. 알림 권한을 끈 상태로 1~2를 반복한다.
   - **기대**: 알림은 오지 않지만 화면 전이는 동일하다(FR-016).
7. 생성이 실패하도록 만든다.
   - **기대**: 완료 알림은 오지 않고, 대기 시간이 지난 뒤 실패 화면으로 전이한다.

### 시나리오 4·5 — 홈 카드 (FR-017~023)

1. 학습 프로젝트 조회를 지연시킨 상태로 홈에 진입한다.
   - **기대**: 카드 자리에 빈 데크 실루엣과 로딩 인디케이터가 보인다.
2. 조회가 끝난다.
   - **기대**: 실제 카드로 교체되고 카드 영역 높이가 변하지 않아 아래 요소가 이동하지
     않는다(SC-006).
3. 카드가 1장일 때와 3장 이상일 때 각각 홈에 진입한다.
   - **기대**: 첫 카드가 기울어지지 않는다(SC-007).
4. 카드 목록을 좌우로 스크롤한 뒤 처음 위치로 되돌린다.
   - **기대**: 각도가 끊김 없이 변하고, 첫 카드가 기준 위치로 돌아오면 다시 0이 된다.

### 시나리오 6 — 공유 진입 (FR-024~029, FR-025a)

1. GitHub 앱에서 임의의 레포지토리를 열고 공유 시트를 연다.
   - **기대**: Git It이 목록에 보인다.
2. Git It을 선택하고 이후 아무 조작도 하지 않는다.
   - **기대**: 링크 입력 화면이 공유된 URL이 채워진 상태로 열리고, "다음"이 추가 조작 없이
     1회 자동 실행되어 직접 붙여넣고 눌렀을 때와 동일하게 레포지토리 확인 단계로 진행된다
     (SC-008).
3. 확인 단계에서 뒤로 돌아와 링크 입력 화면에 머문다.
   - **기대**: 검증이 다시 자동 실행되지 않는다(공유 1건당 1회).
4. 사진 앱에서 이미지를 공유해 공유 시트를 연다.
   - **기대**: Git It이 목록에 보이지 않는다.
5. 로그아웃 상태에서 공유로 진입한다.
   - **기대**: 온보딩·로그인을 마친 뒤 URL이 채워진 링크 입력 화면이 열린다.
6. 로그인을 마치지 않고 앱을 종료한 뒤 다시 실행한다.
   - **기대**: URL이 채워지지 않는다.
7. 생성이 진행 중인 상태에서 공유로 진입한다.
   - **기대**: 등록 화면이 열리지 않고 홈의 진행 중 상태가 보인다. 진행이 끝난 뒤에도 그
     URL이 자동으로 채워지지 않는다.
8. 일반 웹페이지 URL(예: `https://example.com/article`)을 공유한다.
   - **기대**: 링크 입력 화면이 해당 URL이 채워진 상태로 열리고, 자동 실행된 "다음"의 결과로
     기존과 동일한 검증 실패 안내가 같은 화면에 표시된다. 공유 시트가 아무 반응 없이 닫히지
     않는다(FR-029).

### 항목 8 — 프로필 이미지 회귀 확인 (FR-030)

1. 홈 화면의 프로필 영역을 확인한다.
   - **기대**: 프로필 데이터와 무관하게 기존 고정 기본 아바타가 표시된다. 이름·직군 표시는
     기존과 동일하다.
