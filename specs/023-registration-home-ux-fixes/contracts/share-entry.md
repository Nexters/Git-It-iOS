# 계약: 공유 시트 진입 (App / 시스템 경계)

**대상 요구사항**: FR-024~029 (2026-09-02 개정: FR-025a 추가, FR-028·FR-029 확정)

Git It이 iOS 공유 시트와 주고받는 외부 계약이다. 사용자가 다른 앱에서 공유한 URL을
링크 입력 화면의 초기값으로 전달하는 것이 유일한 목적이다.

## 1. 공유 시트 노출 조건

새 앱 확장(Share Extension) target이 활성화 규칙으로 **URL 항목이 포함된 공유만** 받는다.

| 공유 항목 | Git It 노출 |
| --- | --- |
| URL 1개 | 노출 |
| URL 여러 개 | 노출. 형식과 무관하게 첫 번째 URL만 사용한다(FR-028) |
| 텍스트만 | 비노출(FR-024) |
| 이미지·파일만 | 비노출 |

GitHub 앱은 레포지토리를 공유할 때 URL 항목을 제공하므로 이 규칙으로 항목 6의 목적을
충족한다.

## 2. 확장 → 앱 전달

| 요소 | 값 |
| --- | --- |
| 전달 매체 | App Group 공유 컨테이너 |
| 기록 내용 | 공유된 첫 번째 URL 원문 문자열 1건 |
| 앱 실행 신호 | 컨테이너 앱 커스텀 URL 스킴 |

- App Group 식별자와 URL 스킴 문자열은 `AppModuleName.swift`에서 확정하고 앱·확장 양쪽
  entitlements에 함께 등록한다.
- 확장은 URL을 검증하지 않는다. 저장소 링크인지 판정하지 않고 URL 항목의 첫 번째 값을 그대로
  기록하며, 검증은 앱의 기존 링크 검증 경로가 담당한다(FR-029, R-014). 확장은 이 판정을 위해
  Data 패키지를 참조하지 않는다.
- URL을 쿼리 문자열로 실어 보내지 않는다. 사용자 데이터를 URL에 노출하지 않기 위해
  컨테이너로 전달한다.

## 3. 앱의 소비 규칙

| 조건 | 기대 |
| --- | --- |
| 인증 완료 상태 | 링크 입력 화면이 해당 URL이 채워진 상태로 열린다(FR-025) |
| 화면 랜딩 직후 | "다음"이 사용자가 누른 것과 동일하게 1회 자동 실행된다(FR-025a) |
| 미인증 상태 | 기존 진입 흐름을 마친 뒤 채워진 상태로 열린다(FR-026) |
| 미인증 상태에서 앱 종료 | URL은 버려지고 재실행 시 채워지지 않는다(FR-026) |
| 생성 진행 중 | 등록 화면을 열지 않고 홈의 진행 중 상태를 보여주며 URL을 버린다(FR-027) |
| GitHub 레포지토리 링크가 아닌 URL | 링크 입력 화면이 열리고, 자동 실행된 "다음"의 결과로 기존 검증 실패 안내가 같은 화면에 표시된다(FR-025a, FR-029) |
| URL을 얻지 못함 | 빈 링크 입력 화면을 열고 자동 실행하지 않는다 |

- 앱은 컨테이너에서 값을 **읽는 즉시 컨테이너에서 삭제**한다. 이후 수명은 앱 실행 중
  메모리로만 유지한다(R-011).
- 값은 링크 입력 초기값으로 1회만 소비된다.

## 4. 빌드 구성 계약

| 대상 | 변화 |
| --- | --- |
| `AppModuleName.swift` | 확장 target 추가, App Group entitlement, `CFBundleURLTypes` 등록 |
| `GitIt.entitlements` | App Group 추가 |
| 확장 entitlements(신규) | 같은 App Group |
| 확장 Info.plist | `NSExtension` 활성화 규칙(URL 한정) |

확장 target은 프로젝트 내부 패키지를 의존성으로 갖지 않는다. URL 판정을 하지 않으므로
`DataExternalRepository` 참조가 필요 없다(R-014).

manifest와 확장 소스는 함께 있어야 `tuist generate`가 성립하므로 하나의 통합 단위로
구현한다([plan.md](../plan.md)의 실행 단위 참조).
