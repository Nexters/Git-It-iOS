# 데이터 모델: 사용자 노출 문자열 현지화 적용

**기능**: [spec.md](./spec.md) | **조사**: [research.md](./research.md)

이 기능의 “데이터”는 런타임 상태가 아니라 빌드에 포함되는 현지화 리소스와 그 조회 경로다. 저장·전송
모델은 바뀌지 않는다.

## 1. 현지화 리소스 (String Catalog 테이블)

모듈이 소유하는 `.xcstrings` 파일 하나. 명세의 “현지화 리소스”에 해당한다.

| 속성 | 규칙 |
| --- | --- |
| 소유 target | `UIComponent`, `Feature`, `GitIt` 중 하나. 파일은 그 target의 리소스로만 빌드된다(FR-005) |
| 테이블 이름 | 파일 이름에서 확장자를 뗀 이름. `UIComponent`·`GitIt`은 `Localizable`, `Feature`는 흐름 이름(`Settings`, `Quiz` 등). 같은 target 안에서 유일하다 |
| 위치 | [research.md 결정 4](./research.md#결정-4-카탈로그-배치와-테이블-이름) |
| 소스 언어 | `ko` |
| 지원 언어 | `ko`만(FR-008). 다른 언어 값을 두지 않는다 |
| 항목 | 아래 §2의 현지화 항목 0개 이상 |

## 2. 현지화 항목

하나의 사용자 노출 문구. 명세의 “현지화 항목”에 해당한다.

| 속성 | 타입 | 규칙 |
| --- | --- | --- |
| 키 | Swift 식별자 문자열 | lowerCamelCase, `<화면·컴포넌트><용도>`. 테이블 안에서 유일하다. 한국어 값을 바꿔도 유지한다(FR-013) |
| 한국어 값 | 문자열 | 변경 전 리터럴과 글자 단위로 같다. 줄바꿈 `\n`도 유지한다(FR-002) |
| 주석 | 문자열, 필수 | 표시 위치와 의미. 보간 항목은 인자마다 의미를 적는다(FR-003) |
| 인자 | 0개 이상 | 이름 있는 위치 지정자(`%1$(count)lld`, `%1$(name)@`). 수량은 정수 지정자를 쓴다(FR-004) |
| 추출 상태 | `manual` | 컴파일러 추출 항목을 두지 않는다 |
| 생성 심볼 | `LocalizedStringResource` | 인자 없음 → `static var`, 인자 있음 → 인자 레이블을 가진 `static func` |

**검증 규칙**

- 같은 한국어 값이 여러 항목에 있을 수 있으며, 용도가 다르면 반드시 다른 키를 가진다.
- 주석이 빈 항목, 번역 상태가 `ko` 외 언어로 추가된 항목은 두지 않는다.
- 서버·사용자 입력 값, 로그, 진단 메시지, 프리뷰 문자열, 테스트 픽스처는 항목으로 만들지 않는다(FR-006·FR-007).

## 3. 문구 전용 타입 `LocalizedText`

모듈이 소유하는 현지화 문구 조회 진입점. 계약은 [contracts/localized-text.md](./contracts/localized-text.md)가 정한다.

| 관계 | 규칙 |
| --- | --- |
| `LocalizedText` ↔ target | target마다 정확히 하나, `internal` |
| `LocalizedText.<Table>` ↔ 테이블 | 테이블마다 중첩 enum 하나. `UIComponent`·`GitIt`은 `Localizable` 테이블 하나를 쓰되 중첩 enum은 컴포넌트·기능 단위로 나눌 수 있다 |
| 멤버 ↔ 항목 | 항목마다 멤버 하나. 멤버 이름은 키에서 중첩 enum 이름과 같은 첫 단어를 뗀 이름이다(첫 단어가 다르면 키 그대로) |
| 반환 | 항상 `String` |

## 4. 수명과 상태 전이

- 항목은 **추가 → 값 수정 → 제거**만 있다. 키 변경은 제거 후 추가로 다룬다.
- 앱 언어가 바뀌면 iOS가 프로세스를 다시 시작하므로 조회 결과를 캐시하지 않고 호출 시점에 해석한다.
- 이후 언어를 추가하면 카탈로그에 언어 값만 추가하고 `LocalizedText`와 호출부는 바꾸지 않는다(FR-012).
