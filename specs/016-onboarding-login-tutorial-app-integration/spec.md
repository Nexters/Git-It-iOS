## 변경 시나리오와 테스트 *(필수)*

### 시나리오 1 - 앱 시작 상태에 맞는 진입 화면으로 이동한다 (우선순위: P1)

사용자는 앱을 시작하면 세션 복구 결과에 따라 미인증 상태에서는 튜토리얼로, 인증 및 큐레이션이 완료된 상태에서는 MainShell로 이동하며, 인증 후 큐레이션이 남은 경우에는 완료하지 않은 큐레이션 단계부터 이어서 진행한다. 복구 가능한 실패에서는 인증 여부를 추정하지 않고 복구 전용 오류 상태에서 명시적으로 재시도한다.

**주요 행위자**: 앱 사용자

**우선순위 이유**: 앱 시작점이 실제 제품 흐름과 연결되어야 나머지 온보딩 화면과 기능이 사용자에게 도달할 수 있다.

**독립 테스트**: fake composition으로 세션 복구 결과를 각각 주입하여 앱 시작 후 표시되는 root를 검증한다.

**수용 시나리오**:

1. **전제** 사용자가 인증되지 않았다, **실행** 앱을 시작한다, **결과** splash 이후 튜토리얼 첫 페이지가 표시된다.
2. **전제** 사용자가 인증 및 큐레이션을 완료했다, **실행** 앱을 시작한다, **결과** MainShell이 표시된다.
3. **전제** 인증된 멤버의 프로필에서 분야 또는 코드 이해 수준 중 하나 이상이 null이다, **실행** 앱을 시작한다, **결과** 두 선택을 모두 초기화하고 분야 선택 단계부터 전체 큐레이션을 다시 진행한다.
4. **전제** 한 번의 앱 시작 과정이 진행 중이다, **실행** root 화면이 다시 평가된다, **결과** 세션 복구 요청은 중복 실행되지 않는다.
5. **전제** 인증 세션은 있지만 멤버 조회가 404를 반환한다, **실행** 앱이 회원 상태를 판정한다, **결과** 로컬 인증 세션을 정리하고 tutorial부터 신규 가입 흐름을 시작한다.
6. **전제** 세션 복구가 복구 가능한 실패를 반환했다, **실행** 사용자가 복구 오류 화면을 확인하고 다시 시도한다, **결과** 저장된 인증 상태를 정리하거나 tutorial 및 Apple 로그인으로 이동하지 않고 재시도 요청을 정확히 1회 실행한다.

### 시나리오 2 - 튜토리얼과 법적 동의를 거쳐 Apple 로그인을 완료한다 (우선순위: P1)

미인증 사용자는 3페이지 튜토리얼을 탐색하고 Apple 시작 CTA를 선택한 뒤 필수 약관에 동의해야 Apple 로그인을 실행할 수 있다.

**주요 행위자**: 미인증 사용자

**우선순위 이유**: 로그인과 법적 동의의 순서를 보장하는 핵심 진입 흐름이며, 동의 없는 인증 요청을 방지해야 한다.

**독립 테스트**: 튜토리얼 page state, 약관 sheet state, Apple 로그인 호출 횟수와 로그인 결과 상태를 reducer test로 검증한다.

**수용 시나리오**:

1. **전제** 튜토리얼이 표시된다, **실행** 사용자가 좌우로 넘긴다, **결과** 3개 페이지와 page indicator가 같은 현재 페이지를 나타낸다.
2. **전제** 필수 약관에 동의하지 않았다, **실행** Apple 시작 CTA를 누른다, **결과** 약관 sheet가 표시되고 Apple 로그인은 호출되지 않는다.
3. **전제** 약관 sheet가 표시되었다, **실행** 사용자가 취소하거나 닫는다, **결과** 로그인은 실행되지 않고 기존 튜토리얼 페이지가 유지된다.
4. **전제** 필수 약관을 모두 선택했다, **실행** 계속하기를 누른다, **결과** sheet가 닫히고 Apple 로그인이 정확히 1회 실행된다.
5. **전제** 로그인이 취소되거나 일시적으로 실패했다, **실행** 결과가 반환된다, **결과** 사용자는 튜토리얼에 머물며 원인을 구분할 수 있고 다시 시도할 수 있다.
6. **전제** 저장된 필수 약관 동의 버전이 현재 정책 버전과 모두 일치한다, **실행** Apple 시작 CTA를 누른다, **결과** 중복 동의 없이 Apple 로그인을 실행한다.
7. **전제** 필수 정책 중 하나의 현재 버전이 저장된 동의 버전과 다르다, **실행** Apple 시작 CTA를 누른다, **결과** 변경된 현재 정책에 다시 동의하기 전에는 로그인하지 않는다.
8. **전제** 앱 설치 단위의 유효한 필수 약관 동의 기록이 있다, **실행** 로그아웃 또는 session invalidation 후 Apple 시작 CTA를 누른다, **결과** 동의 기록을 유지하고 중복 동의 없이 Apple 로그인을 실행한다.
9. **전제** 외부 브라우저 열기 요청이 실패했다, **실행** 사용자가 두 필수 항목을 직접 선택하고 계속하기를 누른다, **결과** 열기 요청 실패와 재시도 수단을 확인할 수 있고 Apple 로그인은 정확히 1회 실행된다.

### 시나리오 3 - 분야와 코드 이해 수준을 선택해 큐레이션을 완료한다 (우선순위: P1)

로그인한 사용자는 분야와 코드 이해 수준을 순서대로 하나씩 선택하고 큐레이션을 제출한 뒤 MainShell로 이동한다.

**주요 행위자**: 로그인 후 큐레이션이 필요한 사용자

**우선순위 이유**: 인증 후 제품의 개인화 흐름을 완료하고 실제 주요 화면으로 진입하기 위한 필수 단계다.

**독립 테스트**: 선택 전후 CTA 상태, 앞뒤 단계 이동과 선택값 보존, 분야 선택에서의 로그아웃, 제출 인자, 중복 방지, 실패 후 상태 보존과 성공 delegate를 reducer test로 검증한다.

**수용 시나리오**:

1. **전제** 분야를 선택하지 않았다, **실행** 분야 화면을 확인한다, **결과** 다음 CTA가 비활성화된다.
2. **전제** Front-end, Back-end, iOS, Android 중 하나를 선택했다, **실행** 다음 CTA를 누른다, **결과** 선택이 유지된 채 코드 이해 수준 화면으로 이동한다.
3. **전제** 코드 이해 수준을 선택하지 않았다, **실행** 완료 CTA를 확인한다, **결과** 제출할 수 없다.
4. **전제** 분야와 코드 이해 수준을 모두 선택했다, **실행** 완료 CTA를 빠르게 여러 번 누른다, **결과** 큐레이션 요청은 정확히 1회 실행된다.
5. **전제** 큐레이션 제출이 실패했다, **실행** 오류 결과가 반환된다, **결과** 기존 선택이 유지되고 다시 시도할 수 있다.
6. **전제** 큐레이션 제출이 성공했다, **실행** 완료 결과가 반환된다, **결과** MainShell로 이동한다.
7. **전제** 분야 선택 화면이 표시된다, **실행** 사용자가 뒤로 가기를 선택한다, **결과** 로그아웃을 정확히 1회 실행하고 큐레이션을 종료한 뒤 Apple 로그인 CTA가 있는 tutorial 3페이지로 전환한다.
8. **전제** 코드 이해 수준 화면에서 선택값이 존재한다, **실행** 사용자가 뒤로 가기를 선택한다, **결과** 로그아웃이나 큐레이션 제출 없이 현재 큐레이션 선택값을 보존하고 분야 선택 화면으로 돌아간다.

### 시나리오 4 - 디자인 근거와 접근성을 갖춘 화면을 검증한다 (우선순위: P2)

개발자와 리뷰어는 각 화면의 독립 Preview를 Figma 개별 node와 비교하고, 작은 화면·Dynamic Type·VoiceOver·Reduce Motion 환경에서도 핵심 흐름이 유지됨을 확인한다.

**주요 행위자**: 앱 사용자, 개발자, 리뷰어

**우선순위 이유**: 실제 사용자 경험과 디자인 정합성을 재현 가능한 근거로 검증하고 접근성 회귀를 방지한다.

**독립 테스트**: 각 SwiftUI View의 Preview를 `iPhone 17 Pro Max` 기준으로 렌더링해 Figma node와 비교하고 접근성 속성 및 환경별 동작을 확인한다.

**수용 시나리오**:

1. **전제** Figma 대응 화면을 검토한다, **실행** 해당 View 파일의 Preview를 연다, **결과** node ID 또는 상태가 표시된 독립 상태를 즉시 비교할 수 있다.
2. **전제** Dynamic Type 또는 작은 화면을 사용한다, **실행** 튜토리얼과 큐레이션을 진행한다, **결과** 필수 문구와 CTA가 잘리거나 접근 불가능해지지 않는다.
3. **전제** VoiceOver를 사용한다, **실행** 페이지 표시기와 선택 카드를 탐색한다, **결과** 현재 페이지와 선택 상태가 색상 외의 의미로 전달된다.
4. **전제** Reduce Motion이 활성화되었다, **실행** splash에서 다음 단계로 전환한다, **결과** 장식 동작은 축소되지만 정보와 기능 순서는 유지된다.

### 예외·경계 사례

- **App root 상태**: `restoring`, `onboarding`, `mainShell` 중 정확히 하나의 현재 제품 진입점 및 session invalidation에 따른 전환을 나타낸다. 복구 전용 오류 `restoreError`는 App root가 아니라 `onboarding` 내부 phase다.
- **Tutorial 페이지**: 세 페이지의 순서, 표시 문구, 장식용 illustration, Figma 근거 node를 나타낸다.

## 가정

- 기준 브랜치 `feature/all-usecases`에 존재하는 Domain UseCase protocol과 `OnboardingFeature`를 확장하며 동일 책임의 새 인증·큐레이션 계약을 중복 생성하지 않는다.

- 튜토리얼 내부의 축소 앱 화면은 변경 가능한 장식 요소이며 실제 제품 Feature나 Domain 흐름에 연결하지 않는다.
- 로그인과 큐레이션 오류는 기존 Domain 오류 의미를 유지하며 서버 원문이나 기술적 세부 정보를 사용자에게 그대로 노출하지 않는다.
- 기존 DesignSystem과 UIComponent에 같은 의미의 토큰 또는 컴포넌트가 있으면 이를 재사용한다.
- Career 카드의 정확한 문구와 `CareerLevel` 매핑은 `/speckit-plan`에서 지정 Figma node를 직접 조회한 근거로 확정한다.
- MainShell의 내부 기능 구현은 이 명세 범위가 아니며 onboarding 완료 후 도달 가능한 root 연결까지만 포함한다.
- 로컬 정책 동의 기록은 앱 설치 단위의 로그인 전 통과 조건이며, 계정별 법적 동의 증빙을 대신하지 않는다.
