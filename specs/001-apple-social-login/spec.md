## Clarifications

### Session 2026-08-10

- Q: Apple 인증 이후 Git It 로그인 상태는 어떤 경계를 통해 성립하고 유지되는가? → A: Apple 인증 결과를 자체 서버와 교환해 액세스 토큰과 리프레시 토큰을 발급받고, 로그아웃하지 않은 동안 자동 로그인을 유지한다.
- Q: 자체 서버 엔드포인트가 확정되기 전에는 어떻게 개발과 검증을 진행하는가? → A: 실제 서버 연결과 교체할 수 있는 동일 경계의 Mock을 먼저 구현하고, 엔드포인트 확정 후 실제 연결로 대체한다.
- Q: 자동 로그인 종료 조건을 검증하기 위한 최소 로그아웃을 이번 기능에 포함하는가? → A: 포함한다. 로그아웃 시 액세스 토큰과 리프레시 토큰을 모두 삭제하고 로그인 화면으로 돌아간다.
- Q: 액세스 토큰 만료 후 토큰 갱신 실패를 어떻게 처리하는가? → A: 액세스 토큰은 자동 갱신하고, 일시적 통신 실패에는 토큰을 유지한 채 재시도하며, 리프레시 토큰이 거부되거나 만료된 경우에만 두 토큰을 삭제하고 로그인 화면으로 이동한다.
- Q: 로그아웃할 때 자체 서버의 리프레시 토큰도 폐기해야 하는가? → A: 로컬 토큰을 즉시 삭제해 로그아웃을 완료하고, 서버 연결이 가능하면 리프레시 토큰 폐기를 요청하되 서버 요청 실패가 로컬 로그아웃을 막지 않도록 한다.
- Q: “소셜 로그인 토큰을 통해서만 지원”의 정확한 토큰 경계는 무엇인가? → A: Apple 토큰은 Git It 계정 생성·식별의 유일한 자격 증명이며, 서버 확인 후 Git It 액세스·리프레시 토큰으로 로그인 상태를 유지한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Apple 계정으로 처음 로그인 (Priority: P1)

로그아웃 상태의 사용자는 Apple 로그인을 선택하고 본인의 Apple 계정으로 인증하여 별도의 비밀번호를 만들지 않고 Git It 사용을 시작한다. 사용자가 이메일 가리기를 선택하거나 이름 제공을 허용하지 않아도, Apple이 유효한 사용자임을 확인하면 로그인할 수 있다.

**Why this priority**: 사용자가 앱에 진입할 수 있게 하는 핵심 흐름이며, 이 흐름만으로도 Apple 로그인의 최소 사용자 가치를 제공한다.

**Independent Test**: 계정 정보가 없는 새 사용자 상태에서 Apple 로그인을 완료한 뒤 하나의 Git It 계정이 생성되고 인증된 첫 화면에 도달하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Git It 계정과 연결된 적이 없는 유효한 Apple 계정의 로그아웃 사용자, **When** Apple 로그인을 선택하고 인증을 승인하면, **Then** Git It 계정이 하나 생성되고 사용자는 인증된 첫 화면으로 이동한다.
2. **Given** 새 사용자가 Apple의 이메일 가리기를 선택한 상태, **When** 인증을 승인하면, **Then** 가려진 이메일 선택이 존중되고 사용자는 추가 이메일 입력 없이 로그인한다.
3. **Given** Apple 로그인이 진행 중인 상태, **When** 사용자가 로그인 동작을 반복해 선택하면, **Then** 중복 인증이 시작되지 않고 진행 중임을 알 수 있다.

---

### User Story 2 - 기존 Apple 계정으로 다시 로그인 (Priority: P2)

이전에 Apple 로그인을 완료한 사용자는 같은 Apple 계정으로 다시 인증할 때 기존 Git It 계정으로 돌아간다. Apple이 이름이나 이메일을 다시 제공하지 않더라도 기존 계정을 찾을 수 있으며, 자체 서버가 발급한 로그인 상태를 갱신할 수 있고 사용자가 로그아웃하지 않았다면 앱 재실행 시 인증을 반복하지 않는다. 사용자가 로그아웃하면 저장된 로그인 상태를 모두 종료하고 다음 앱 진입에서 다시 로그인한다.

**Why this priority**: 반복 방문자가 계정 중복이나 불필요한 인증 없이 연속적으로 앱을 사용할 수 있어야 안정적인 로그인 경험이 완성된다.

**Independent Test**: 미리 Apple 계정과 연결된 Git It 계정을 준비하고, 프로필 정보가 다시 전달되지 않는 조건에서 로그인 및 앱 재실행 후 같은 계정으로 진입하는지 확인한다. 이어서 로그아웃하고 앱을 다시 실행했을 때 로그인 화면에 머무는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Apple 계정과 연결된 기존 Git It 계정이 있는 로그아웃 사용자, **When** 같은 Apple 계정으로 인증하면, **Then** 새 계정이 생성되지 않고 기존 계정으로 로그인한다.
2. **Given** Apple이 이전 인증에서만 이름과 이메일을 제공한 사용자, **When** 해당 정보 없이 다시 인증하면, **Then** 동일한 Git It 계정으로 로그인한다.
3. **Given** 자체 서버가 발급한 갱신 가능한 로그인 상태로 앱을 종료했고 로그아웃하지 않은 사용자, **When** 앱을 다시 실행하면, **Then** Apple 인증을 다시 요구하지 않고 인증된 첫 화면으로 이동한다.
4. **Given** 로그인한 사용자, **When** 로그아웃을 선택하면, **Then** 액세스 토큰과 리프레시 토큰이 로컬에서 즉시 삭제되고 로그인 화면으로 이동하며 앱을 다시 실행해도 자동 로그인되지 않는다. 서버에 연결할 수 있으면 리프레시 토큰 폐기도 요청한다.
5. **Given** 액세스 토큰은 만료되었지만 리프레시 토큰이 유효한 사용자, **When** 앱이 로그인 상태를 복원하면, **Then** 액세스 토큰을 자동 갱신하고 Apple 인증 없이 기존 계정으로 진입한다.

---

### User Story 3 - 취소 및 오류에서 안전하게 복구 (Priority: P3)

사용자는 Apple 인증을 취소하거나 인증 중 연결 문제 또는 외부 서비스 오류가 발생해도 잘못 로그인되거나 멈춘 상태에 남지 않는다. 사용자는 현재 상태와 다음 행동을 이해하고 다시 시도할 수 있다.

**Why this priority**: 실패·취소 경로가 계정 보안과 로그인 신뢰도에 직접 영향을 주며, 사용자가 앱 진입을 다시 시도할 수 있어야 한다.

**Independent Test**: 취소, 연결 끊김, 외부 인증 실패, 저장된 로그인 상태 무효화 조건을 각각 재현하여 보호된 화면에 진입하지 않고 안정적인 로그인 화면과 재시도 수단을 제공하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Apple 인증 화면을 연 로그아웃 사용자, **When** 인증을 취소하면, **Then** 오류 경고 없이 로그인 화면으로 돌아오며 계정이나 로그인 상태가 생성되지 않는다.
2. **Given** 인증 중 복구 가능한 오류가 발생한 상태, **When** 인증이 실패하면, **Then** 사용자는 이해 가능한 실패 안내와 재시도 동작을 보고 로그아웃 상태를 유지한다.
3. **Given** 직전 인증이 실패한 사용자, **When** 문제를 해소한 뒤 다시 시도하여 인증을 승인하면, **Then** 이전 실패에 방해받지 않고 정상적으로 로그인한다.
4. **Given** 저장된 로그인 상태 또는 Apple 계정 연결이 더 이상 유효하지 않은 사용자, **When** 앱이 해당 상태를 확인하면, **Then** 인증된 콘텐츠 접근을 중단하고 다시 로그인할 수 있는 화면을 제공한다.
5. **Given** 토큰 갱신 중 일시적인 통신 실패가 발생한 사용자, **When** 갱신을 완료하지 못하면, **Then** 저장된 토큰을 삭제하거나 강제로 로그아웃하지 않고 보호된 콘텐츠는 노출하지 않으며 재시도할 수 있다.
6. **Given** 자체 서버가 리프레시 토큰을 거부하거나 만료되었다고 확인한 사용자, **When** 갱신 응답을 처리하면, **Then** 두 토큰을 모두 삭제하고 로그인 화면으로 이동한다.

### Edge Cases

- 사용자가 실제 이메일 대신 Apple의 이메일 가리기를 선택하거나 이메일 제공을 거부한다.
- Apple은 이름과 이메일을 최초 승인 때만 제공하고 이후 인증에서는 제공하지 않는다.
- 사용자가 인증 도중 앱을 백그라운드로 보내거나 앱이 종료된 뒤 다시 실행한다.
- 사용자가 로그인 동작을 빠르게 여러 번 선택한다.
- 인증 도중 네트워크가 끊기거나 Apple 인증 서비스를 일시적으로 사용할 수 없다.
- 인증이 성공한 직후 앱의 계정 또는 세션 처리에 실패한다.
- 액세스 토큰은 만료되었지만 리프레시 토큰은 유효하거나, 리프레시 토큰도 더 이상 유효하지 않다.
- 토큰 갱신 요청 중 일시적인 네트워크 오류가 발생한다.
- 토큰 갱신이 진행 중일 때 사용자가 로그아웃한다.
- 로그아웃 시 서버의 리프레시 토큰 폐기 요청이 일시적인 통신 오류로 실패한다.
- 기존 로그인 상태가 만료되거나 Apple 계정 연결 권한이 철회된다.
- 동일한 기기에서 이전과 다른 Apple 계정으로 인증한다.
- 같은 이메일의 기존 Git It 계정이 있지만 Apple 계정과 명시적으로 연결된 적은 없다.
- 연결된 Git It 계정이 비활성화되었거나 이용할 수 없는 상태다.

## Requirements *(mandatory)*

### Scope

**In Scope**:

- 로그아웃 상태에서 Apple 로그인을 시작하고 완료하는 사용자 흐름
- 최초 사용자의 Git It 계정 생성과 재방문자의 기존 계정 식별
- 성공한 로그인 상태의 생성, 앱 재실행 시 복원, 유효하지 않은 상태의 해제
- Apple 인증 결과를 자체 서버의 Git It 로그인 상태로 교환하고 액세스 토큰과 리프레시 토큰으로 유지하는 흐름
- Apple 인증 토큰만을 Git It 계정 생성·식별의 자격 증명으로 허용하고 별도의 자체 회원가입이나 비밀번호 인증을 제공하지 않는 계정 정책
- 액세스 토큰과 리프레시 토큰을 모두 삭제하고 자동 로그인을 종료하는 최소 로그아웃 흐름
- 로그아웃 시 자체 서버에 리프레시 토큰 폐기를 요청하되 통신 실패와 관계없이 로컬 로그아웃을 완료하는 흐름
- 취소, 중단, 외부 인증 실패 및 계정 이용 불가 상태의 사용자 안내와 복구
- Apple이 허용한 최소 프로필 정보 및 이메일 가리기 선택의 처리
- 자체 서버 엔드포인트 확정 전 실제 연결과 같은 경계에서 동작하는 교체 가능한 Mock을 통한 개발과 검증

**Out of Scope**:

- Apple 이외의 소셜 로그인 제공자 추가
- 자체 회원가입, 이메일·비밀번호 로그인 및 그 밖의 비소셜 자격 증명으로 Git It 계정을 생성하거나 식별하는 방식
- 이메일 일치만을 근거로 한 기존 계정 자동 병합 또는 계정 연결 화면
- 계정 삭제, Apple 연결 해제 및 프로필 편집
- Apple 계정 자체의 복구, 비밀번호 변경 또는 보안 설정 관리
- 엔드포인트와 요청·응답 계약이 확정되기 전 실제 자체 서버에 연결하는 작업

### Functional Requirements

- **FR-001**: 시스템은 로그아웃 사용자에게 Apple 로그인임을 명확히 식별할 수 있는 시작 동작을 제공해야 한다.
- **FR-002**: 시스템은 사용자의 명시적인 선택이 있을 때만 Apple 인증을 시작해야 한다.
- **FR-003**: 시스템은 인증 진행 상태를 사용자에게 표시하고 하나의 로그인 시도 중 중복 인증 시작을 막아야 한다.
- **FR-004**: 시스템은 Apple이 제공하는 이메일 공개 또는 가리기 선택을 존중해야 하며, 사용자가 허용하지 않은 프로필 정보를 요구해서는 안 된다.
- **FR-005**: 시스템은 처음 인증한 유효한 Apple 계정에 대해 하나의 Git It 계정을 생성하고 해당 Apple 계정과 연결해야 한다.
- **FR-006**: 시스템은 이름 또는 이메일이 제공되지 않아도 Apple이 유효한 사용자 식별을 제공하면 계정 생성 또는 로그인을 완료해야 한다.
- **FR-007**: 시스템은 이후 같은 Apple 계정으로 인증한 사용자를 동일한 Git It 계정으로 식별하고 중복 계정을 생성하지 않아야 한다.
- **FR-008**: 시스템은 Apple 인증 결과를 자체 서버가 확인하고 액세스 토큰과 리프레시 토큰을 모두 발급한 뒤에만 유효한 Git It 로그인 상태를 만들고 인증된 첫 화면으로 이동해야 한다.
- **FR-009**: 시스템은 자체 서버가 발급한 로그인 상태를 앱 재실행 후 복원하고, 사용자가 로그아웃하지 않았으며 리프레시 토큰으로 로그인 상태를 갱신할 수 있으면 Apple 인증 과정을 생략해야 한다.
- **FR-010**: 시스템은 리프레시 토큰 거부·만료, Apple 계정 연결 권한 철회 또는 계정 이용 불가로 로그인 상태가 유효하지 않으면 해당 상태를 해제하고 인증된 콘텐츠 접근을 차단해야 한다.

- **FR-017**: Apple 로그인 시작 동작, 진행 상태, 실패 안내 및 재시도 동작은 보조 기술을 사용하는 사용자도 의미와 상태를 식별하고 조작할 수 있어야 한다.

- **FR-020**: 시스템은 로그아웃이 완료된 뒤 앱을 다시 실행해도 이전 로그인 상태를 복원하거나 진행 중이던 토큰 갱신 결과로 자동 로그인해서는 안 된다.
- **FR-021**: 시스템은 액세스 토큰이 만료되고 리프레시 토큰이 유효하면 사용자의 추가 입력 없이 액세스 토큰을 갱신한 뒤 기존 로그인 상태를 이어가야 한다.

- **FR-023**: 시스템은 자체 서버가 리프레시 토큰을 거부하거나 만료되었다고 확인한 경우에만 두 토큰을 삭제하고 Apple 로그인이 필요한 화면으로 이동해야 한다.
- **FR-024**: 시스템은 로그아웃 시 자체 서버에 리프레시 토큰 폐기를 요청해야 하며, 서버 요청의 성공 여부나 일시적인 통신 실패가 로컬 로그아웃 완료를 지연하거나 되돌려서는 안 된다.
- **FR-025**: 시스템은 저장된 액세스 토큰과 리프레시 토큰을 기기의 보호된 영역에서 관리하고 다른 앱이나 사용자에게 노출되는 오류·진단 정보에서 읽을 수 없도록 해야 한다.
- **FR-026**: 시스템은 Apple 인증 토큰을 Git It 사용자 계정 생성 및 식별을 위한 유일한 자격 증명으로 허용해야 하며, 자체 회원가입이나 이메일·비밀번호 등 별도의 자격 증명으로 계정을 생성하거나 로그인하는 경로를 제공해서는 안 된다.
- **FR-027**: 시스템은 Apple 인증 토큰을 자체 서버가 확인한 뒤 Git It 액세스 토큰과 리프레시 토큰을 발급하여 로그인 상태를 유지해야 하며, Apple 인증 토큰 자체를 Git It 로그인 세션 토큰으로 사용해서는 안 된다.

- **SC-003**: Apple이 인증 성공을 확인한 시점부터 95% 이상의 로그인에서 3초 이내에 인증된 첫 화면이 표시된다.
- **SC-004**: 동일한 Apple 계정으로 최초 로그인과 반복 로그인을 수행하는 모든 검증 시나리오에서 Git It 계정이 정확히 하나만 생성되고 같은 계정으로 진입한다.
- **SC-005**: 이름 미제공, 실제 이메일 공개, 이메일 가리기 각각의 검증 시나리오에서 유효한 Apple 사용자 식별이 있으면 100% 로그인할 수 있다.
- **SC-006**: 취소, 인증 실패, 로그인 상태 만료 및 권한 철회 검증 시나리오의 100%에서 인증된 콘텐츠가 노출되지 않고 3초 이내에 안정적인 로그인 또는 복구 화면을 제공한다.

- **SC-008**: 실제 자체 서버 엔드포인트가 없어도 Mock을 사용하는 서버 의존 로그인 검증 시나리오의 100%를 반복 실행할 수 있고, 이후 실제 서버 연결로 교체해도 사용자 로그인 흐름의 합격 기준이 유지된다.
- **SC-009**: 모든 로그아웃 검증 시나리오에서 액세스 토큰과 리프레시 토큰이 제거되고 3초 이내에 로그인 화면이 표시되며, 앱 재실행 후에도 인증된 콘텐츠가 노출되지 않는다.
- **SC-010**: 액세스 토큰 만료 검증에서 유효한 리프레시 토큰을 가진 사용자는 95% 이상 추가 입력 없이 3초 이내에 로그인 상태를 복원한다.
- **SC-011**: 토큰 갱신의 일시적 통신 실패와 리프레시 토큰 거부·만료 검증 시나리오의 100%에서 각각 토큰 유지·재시도와 토큰 삭제·재로그인으로 구분하여 처리한다.
- **SC-012**: 서버의 리프레시 토큰 폐기 성공·실패 검증 시나리오의 100%에서 로컬 로그아웃은 3초 이내에 완료되고, 서버에 연결할 수 있는 경우 폐기 요청이 전달된다.

## Assumptions

- 이 기능의 대상은 Apple 로그인을 지원하는 기기에서 Git It을 사용하는 일반 사용자다.
- 사용자는 최초 온라인 인증을 완료할 수 있는 네트워크 연결과 사용 가능한 Apple 계정을 보유한다.
- Git It 자체 서버가 Apple 인증 결과를 확인하고 사용자 계정에 대응하는 액세스 토큰과 리프레시 토큰을 발급한다.
- 자체 서버 엔드포인트와 구체적인 요청·응답 계약은 아직 확정되지 않았으며, 이번 계획은 교체 가능한 Mock을 먼저 제공한다.
- Apple이 제공하는 이름과 이메일은 선택 정보이며, 반복 인증에서 다시 제공되지 않을 수 있다.
- 동일한 Apple 계정 식별은 같은 Git It 사용자로 취급하지만 이메일 주소만 같은 계정은 보안상 자동 병합하지 않는다.
- Git It 사용자 계정은 Apple 인증 토큰으로만 생성·식별하며, 자체 회원가입이나 이메일·비밀번호 자격 증명은 지원하지 않는다. Apple 인증 확인 후의 로그인 상태는 자체 서버가 발급한 액세스 토큰과 리프레시 토큰으로 유지한다.
- 계정 삭제, 계정 간 연결 및 다른 로그인 제공자 추가는 별도 계정 관리 기능에서 다룬다.
- 외부 Apple 인증 서비스와 Git It의 계정·로그인 상태 관리 기능을 사용할 수 있어야 한다.
