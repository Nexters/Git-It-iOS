# 기능 명세: 공유 시트에서 GitHub 저장소를 등록하는 Share Extension

**Git-flow 유형**: `feature`

**기능 브랜치**: `feature/share-extension-repository-link`

**브랜치 상태**: `재사용`

**생성일**: 2026-09-05

**상태**: 초안

**입력**: 사용자 설명: "외부 앱(Safari, GitHub 앱 등)의 공유 시트에서 GitHub 레포지토리 URL을 Git-It으로 공유하면, Share Extension 자체 UI 내에서 인증 세션 확인부터 프로젝트 등록 API 호출까지 완결하는 기능. 본 앱은 실행하지 않으며 서버 측 추가 작업은 없다."

## 명확화

### 세션 2026-09-05

- 질문: 앱 업데이트 후 본 앱을 한 번도 실행하지 않아 세션이 아직 공유 저장소로 이전되지 않은 상태에서 공유하면 어떻게 처리하는가? → 답변: 로그인 필요와 구분되는 전용 안내 상태를 두고, 본 앱을 한 번 실행한 뒤 다시 시도하도록 안내한다.
- 질문: Extension으로 등록한 뒤 사용자는 퀴즈 생성 완료를 어떻게 아는가? → 답변: 알림 권한이 이미 허용된 경우에 한해 Extension이 본 앱과 동일한 생성 리마인더를 예약하고, 권한 요청은 하지 않는다.
- 질문: 본 앱이 백그라운드에 살아 있는 동안 Extension으로 등록하면 목록에 언제 반영되는가? → 답변: 본 앱이 포그라운드로 복귀할 때 프로젝트 목록을 갱신한다.
- 질문: Extension 실패를 어떻게 진단하는가? → 답변: 기존 방식의 로컬 진단 로그만 남기고 토큰·개인정보는 기록하지 않으며, 원격 수집은 하지 않는다.

## 변경 시나리오와 테스트 *(필수)*

### 시나리오 1 - 공유 시트에서 저장소 등록 완결 (우선순위: P1)

Git-It에 로그인한 사용자가 Safari나 GitHub 앱에서 GitHub 저장소 페이지를 보다가 공유 시트에서
Git-It을 선택하면, 호스트 앱 위에 뜬 Extension 화면 안에서 등록을 마치고 원래 앱으로 돌아온다.
본 앱은 실행되지 않는다.

**주요 행위자**: 최종 사용자

**우선순위 이유**: 이 기능의 존재 이유 자체다. 이 시나리오 없이는 나머지 시나리오가 의미를 갖지 않는다.

**독립 테스트**: 로그인 상태의 기기에서 GitHub 저장소 URL을 공유해 Extension 안에서 난이도를 선택하고 등록을
완료한 뒤, 본 앱 프로젝트 목록에서 해당 프로젝트가 선택한 난이도로 보이는지 확인한다.

**수용 시나리오**:

1. **전제** 유효한 세션이 저장되어 있고 공유된 URL이 GitHub 저장소 경로다, **실행** Extension이 실행된다, **결과** 저장소 조회 결과와 난이도 선택지가 표시되고 등록 동작이 활성화된다.
2. **전제** 등록 가능 상태다, **실행** 사용자가 난이도를 선택하고 등록을 실행한다, **결과** 선택한 난이도로 등록 요청이 성공하고 성공 상태가 표시된다.
3. **전제** 등록이 성공해 성공 상태가 표시되어 있다, **실행** 사용자가 닫기를 선택한다, **결과** Extension이 종료되고 호스트 앱이 공유 이전과 같은 화면으로 복귀한다.
4. **전제** 등록이 성공했고 본 앱이 백그라운드에 머물러 있었다, **실행** 사용자가 본 앱으로 복귀한다, **결과** 추가 화면 이동 없이 등록된 프로젝트가 프로젝트 목록에 나타난다.
5. **전제** 등록 요청이 진행 중이다, **실행** 사용자가 등록 실행을 다시 시도한다, **결과** 중복 요청이 발생하지 않는다.
6. **전제** 알림 권한이 이미 허용되어 있다, **실행** 등록이 성공한다, **결과** 본 앱과 동일한 퀴즈 생성 리마인더가 예약된다.
7. **전제** 알림 권한이 미허용 또는 미결정이다, **실행** 등록이 성공한다, **결과** 권한 요청이나 리마인더 예약 없이 완료 상태만 표시된다.

---

### 시나리오 2 - 등록할 수 없는 상황을 즉시 알리기 (우선순위: P2)

공유된 링크가 GitHub 저장소가 아니거나 로그인 세션이 없거나 만료된 경우, 사용자는 Extension 안에서
그 사실과 다음 행동을 즉시 안내받고 잘못된 등록 요청이 발생하지 않는다.

**주요 행위자**: 최종 사용자

**우선순위 이유**: 잘못된 입력과 미로그인은 실제로 자주 발생하며, 안내 없이는 사용자가 원인을 알 수 없다.
등록 경로의 신뢰성을 결정한다.

**독립 테스트**: 비저장소 GitHub URL과 GitHub 외 URL을 공유해 오류 안내가 뜨고 등록이 차단되는지,
로그아웃 상태에서 공유해 로그인 안내가 뜨는지 확인한다.

**수용 시나리오**:

1. **전제** 공유된 URL이 GitHub 저장소 경로가 아니다, **실행** Extension이 실행된다, **결과** URL 오류 상태가 네트워크 호출 없이 표시되고 등록 동작이 제공되지 않는다.
2. **전제** 저장된 세션이 없거나 접근 토큰이 만료되었다, **실행** Extension이 실행된다, **결과** 토큰 갱신을 시도하지 않고 로그인 안내 상태가 표시된다.
3. **전제** 등록 요청에 서버가 인증 오류로 응답했다, **실행** 응답을 처리한다, **결과** 토큰 갱신을 시도하지 않고 로그인 안내 상태로 전환한다.
4. **전제** 사용자는 로그인 상태지만 업데이트 후 본 앱을 실행한 적이 없어 세션이 이전되지 않았다, **실행** Extension이 실행된다, **결과** 로그인 안내가 아닌 앱 실행 필요 안내가 표시되고 저장된 세션은 유지된다.

---

### 시나리오 3 - 실패한 등록의 재시도와 중단 (우선순위: P3)

네트워크 오류나 서버 오류로 등록이 실패하면 사용자는 사유를 확인하고 같은 화면에서 재시도할 수 있으며,
도중에 화면을 닫으면 요청은 취소되고 이후 자동으로 재실행되지 않는다.

**주요 행위자**: 최종 사용자

**우선순위 이유**: 실패 복구는 가치가 있지만, 실패하더라도 사용자는 본 앱에서 등록할 수 있어
P1·P2보다 후순위다.

**독립 테스트**: 네트워크를 차단한 상태에서 등록을 실행해 실패 상태와 재시도 동작을 확인하고,
요청 중 화면을 닫은 뒤 재진입해 자동 재실행이 없음을 확인한다.

**수용 시나리오**:

1. **전제** 네트워크를 사용할 수 없다, **실행** 사용자가 등록을 실행한다, **결과** 실패 상태와 재시도 동작이 표시된다.
2. **전제** 이미 등록된 저장소다, **실행** 사용자가 등록을 실행한다, **결과** 서버가 제공한 사유가 실패 상태로 표시된다.
3. **전제** 등록 요청이 진행 중이다, **실행** 사용자가 Extension을 닫는다, **결과** 요청이 취소되고 미완료 요청을 보관하거나 이후 자동 재실행하지 않는다.

---

### 예외·경계 사례

- 공유 항목이 URL 타입이 아니라 텍스트 타입으로 전달되면 URL 변환을 시도한 뒤 판정한다. 변환에 실패하면 URL 오류 상태다.
- GitHub 호스트지만 저장소를 가리키지 않는 경로(사용자 프로필, 검색 결과, 이슈 목록 등)는 URL 오류 상태다.
- 저장소 경로 뒤에 하위 경로나 쿼리·프래그먼트가 붙은 URL은 소유자·저장소 식별자를 추출해 등록 대상으로 판정한다.
- 공유 항목이 여러 개 전달되면 저장소로 판정 가능한 첫 항목을 대상으로 삼는다.
- 본 앱 복귀 시 목록 갱신이 실패하면 기존에 표시하던 목록을 유지하며, 갱신 실패를 등록 실패로 표시하지 않는다.
- 기기가 부팅 후 한 번도 잠금 해제되지 않은 상태에서는 세션을 읽을 수 없으므로 로그인 안내 상태로 처리한다.
- 기존에 로그인한 사용자의 세션이 아직 공유 저장소로 옮겨지지 않았다면 앱 실행 필요 상태로 안내하며, 세션을 폐기하거나 강제 로그아웃하지 않는다.
- 로컬 판정은 통과했지만 저장소 조회가 404 등으로 실패하면 사유와 재시도 동작을 갖춘 실패 상태로 처리한다.
- 저장소 조회 중 네트워크가 끊기면 실패 상태로 전환하며, 재시도는 조회부터 다시 수행한다.
- 알림 권한 확인이나 리마인더 예약이 실패해도 등록은 성공으로 처리하며 사용자에게 별도 오류를 표시하지 않는다.
- 등록은 성공했으나 사용자가 완료 상태를 보기 전에 Extension이 종료되면 이미 예약된 리마인더는 그대로 유지된다.
- Extension이 메모리 상한으로 종료되면 등록 요청은 완료되지 않은 것으로 간주하며 별도 재실행을 예약하지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

**공유 콘텐츠 수신과 검증**

- **FR-001**: 시스템은 web URL을 공유할 때만 공유 시트에 Git-It Share Extension을 노출해야 한다.
- **FR-002**: 시스템은 공유 항목에서 URL 타입을 우선 수신하고, 텍스트 타입으로 전달된 경우 URL 변환을 보조로 시도해야 한다.
- **FR-003**: 시스템은 공유된 URL이 GitHub 호스트의 저장소 경로 형식인지 네트워크 호출 없이 판정해야 한다.
- **FR-004**: 시스템은 판정에 실패한 URL에 대해 네트워크 호출 없이 오류 상태로 전환하고 등록 동작을 제공하지 않아야 한다.
- **FR-004a**: 시스템은 로컬 판정을 통과한 URL에 대해 본 앱과 동일한 저장소 조회를 수행해 등록 가능 상태의 표시 정보를 확보해야 한다.
- **FR-004b**: 시스템은 저장소 조회가 실패한 경우 등록을 차단하고, 인증 오류면 로그인 필요 상태로, 그 밖의 오류면 사유와 재시도 동작을 갖춘 실패 상태로 전환해야 한다.

**인증 세션 확인**

- **FR-005**: 본 앱과 Extension은 동일한 공유 자격 증명 저장소를 통해 세션을 공유해야 한다.
- **FR-006**: 시스템은 등록 요청 전에 저장된 세션의 유효성을 확인해야 한다.
- **FR-007**: Extension은 어떤 경로로도 토큰 갱신 요청을 발생시키지 않아야 한다.
- **FR-008**: 시스템은 세션이 없거나 접근 토큰이 만료된 경우 갱신 없이 로그인 안내 상태로 전환해야 한다.
- **FR-009**: 시스템은 서버가 인증 오류로 응답한 경우에도 갱신 없이 로그인 안내 상태로 전환해야 한다.
- **FR-010**: 자격 증명 저장소는 기기 최초 잠금 해제 이후 Extension 프로세스에서 읽을 수 있는 접근성 수준과 접근 범위를 보장해야 한다.
- **FR-011**: 시스템은 기존에 로그인한 사용자의 세션을 공유 저장소로 이전하되, 이전 과정에서 사용자를 로그아웃시키지 않아야 한다.
- **FR-011a**: 시스템은 세션 이전이 아직 이루어지지 않은 상태를 로그인 필요 상태와 구분해 판정하고, 본 앱을 한 번 실행한 뒤 다시 시도하도록 안내하는 전용 상태로 전환해야 한다.
- **FR-011b**: 시스템은 앱 실행 필요 상태에서 등록을 차단하되 저장된 세션을 폐기하거나 사용자를 로그아웃시키지 않아야 한다.

**프로젝트 등록**

- **FR-012**: 시스템은 본 앱과 동일한 프로젝트 등록 요청 규격과 검증 규칙을 사용해야 하며, 서버의 신규 엔드포인트나 스펙 변경을 요구하지 않아야 한다.
- **FR-013**: 시스템은 공유된 URL을 등록 대상으로 자동 채우고 사용자가 URL을 직접 입력하도록 요구하지 않아야 한다.
- **FR-014**: 시스템은 등록 가능 상태에서 본 앱과 동일한 퀴즈 난이도 선택지를 제공하고, 사용자가 선택한 값을 등록 요청에 사용해야 한다.
- **FR-014a**: 시스템은 난이도를 선택하지 않은 상태에서도 등록을 실행할 수 있도록 본 앱과 동일한 기본 선택값을 미리 지정해야 한다.
- **FR-015**: 시스템은 요청이 진행 중인 동안 추가 등록 실행을 차단해야 한다.
- **FR-016**: 시스템은 등록 성공 시 완료 상태를 표시하고 결과 상세 조회를 제공하지 않아야 한다.
- **FR-016a**: 시스템은 등록 성공 시 알림 권한이 이미 허용되어 있는 경우에 한해 본 앱과 동일한 퀴즈 생성 리마인더를 예약해야 한다.
- **FR-016b**: Extension은 알림 권한을 요청하지 않아야 하며, 권한이 미허용 또는 미결정이면 리마인더를 예약하지 않고 완료 상태만 표시해야 한다.
- **FR-016c**: 시스템은 권한 확인 또는 리마인더 예약이 실패하더라도 등록 성공 표시와 종료 흐름을 방해하지 않아야 한다.
- **FR-017**: 시스템은 등록 실패 시 서버가 제공한 사유를 사용자가 읽을 수 있는 문구로 표시하고 재시도 동작을 제공해야 한다.
- **FR-018**: 시스템은 사용자가 요청 중 화면을 닫으면 진행 중인 요청을 취소하고, 미완료 요청을 보관하거나 이후 자동으로 재실행하지 않아야 한다.

**화면 상태와 표현**

- **FR-019**: 시스템은 검증 중(로컬 판정과 저장소 조회), 등록 가능, URL 오류, 로그인 필요, 앱 실행 필요, 요청 중, 성공, 실패 상태를 단일 화면 내 전환으로 제공하고 화면 간 이동을 두지 않아야 한다.
- **FR-020**: 시스템은 요청 중 상태를 제외한 모든 상태에서 닫기 동작을 제공해야 한다.
- **FR-021**: 시스템은 등록 가능 상태에서 본 앱의 저장소 확인 화면과 동일한 조회 결과 정보를 표시해야 한다.
- **FR-022**: 시스템은 본 앱의 디자인 시스템 색상·타이포그래피·컴포넌트를 사용해 본 앱과 일관된 화면을 제공해야 한다.
- **FR-023**: 시스템은 호스트 앱 위에 카드 형태로 표시하며 배경에 호스트 앱이 비치도록 해야 한다.
- **FR-024**: 시스템은 종료 시 호스트 앱으로 복귀하며 호스트 앱의 상태를 변경하지 않아야 한다.
- **FR-025**: 시스템은 본 앱을 실행하거나 본 앱 화면으로 이동시키지 않아야 한다.

**본 앱 반영**

- **FR-028**: 본 앱은 포그라운드로 복귀할 때 프로젝트 목록을 갱신해, 백그라운드에 머무는 동안 Extension으로 등록된 프로젝트가 추가 화면 이동 없이 나타나도록 해야 한다.
- **FR-029**: 본 앱의 목록 갱신은 Extension이 남기는 별도 신호에 의존하지 않아야 한다.

**Extension 실행 환경**

- **FR-026**: Extension이 사용하는 코드는 앱 실행, 배지 설정 등 애플리케이션 단위 API에 의존하지 않아야 한다. 로컬 알림 예약은 Extension에서 지원되는 범위 안에서만 사용한다.
- **FR-027**: Extension은 등록 완결에 필요하지 않은 의존성과 Extension을 지원하지 않는 외부 SDK를 포함하지 않아야 한다.
- **FR-030**: 시스템은 URL 판정 실패, 세션 확인 결과, 저장소 조회 실패, 등록 실패의 사유를 기기 내 진단 로그로 남겨야 한다.
- **FR-031**: 진단 로그는 토큰, 자격 증명, 개인정보를 포함하지 않아야 하며 원격으로 수집·전송하지 않아야 한다.

### 핵심 엔터티

- **공유된 저장소 링크**: 호스트 앱에서 전달된 원본 URL과, 로컬 판정으로 추출한 소유자·저장소 식별자.
- **인증 세션**: 본 앱과 Extension이 공유 저장소를 통해 함께 읽는 접근 토큰과 만료 시각. Extension은 읽기 전용으로 사용한다.
- **등록 요청 결과**: 등록 성공 시 서버가 반환하는 프로젝트 식별자와 처리 상태, 실패 시 사용자에게 전달할 사유.
- **Extension 화면 상태**: 검증 중, 등록 가능, URL 오류, 로그인 필요, 앱 실행 필요, 요청 중, 성공, 실패 중 하나이며 각 상태가 허용하는 동작을 정의한다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 로그인한 사용자가 공유 시트에서 Git-It을 선택한 뒤 본 앱을 실행하지 않고 등록 완료 표시까지 도달한다.
- **SC-002**: 공유 시트 선택부터 URL 오류 또는 로그인 필요 판정이 표시되기까지 네트워크 상태와 무관하게 1초 이내다.
- **SC-002a**: 정상 네트워크에서 공유 시트 선택부터 등록 가능 상태가 표시되기까지 본 앱의 저장소 확인 화면과 동등한 시간 이내다.
- **SC-003**: GitHub 저장소 URL과 비저장소 URL 판정이 정의된 검증 사례 전체에서 기대 결과와 일치한다.
- **SC-004**: 세션 없음, 접근 토큰 만료, 서버 인증 오류 세 경우 모두에서 토큰 갱신 요청이 0건이며 로그인 안내 상태로 전환한다.
- **SC-005**: Extension에서 등록한 프로젝트가 본 앱을 포그라운드로 되돌린 직후의 프로젝트 목록에서 추가 화면 이동 없이 확인되며, 선택한 퀴즈 난이도가 그대로 반영된다.
- **SC-006**: 등록 요청 중 화면을 닫은 뒤 재진입했을 때 자동 재실행이 발생하지 않는다.
- **SC-006a**: 알림 권한이 허용된 상태의 등록에서는 리마인더가 예약되고, 미허용·미결정 상태의 등록에서는 권한 요청 프롬프트가 0건이며 예약도 발생하지 않는다.
- **SC-007**: Extension의 최대 메모리 사용량이 iOS가 Share Extension에 부여하는 상한 이내이며 실기기 측정에서 종료가 발생하지 않는다.
- **SC-008**: 기존 로그인 사용자가 이 변경이 적용된 버전으로 갱신한 뒤 본 앱을 한 번 실행하면, 재로그인 없이 본 앱과 Extension 모두에서 세션이 인식된다. 본 앱 실행 전 공유하면 로그인 필요가 아닌 앱 실행 필요 안내가 표시된다.
- **SC-009**: 변경 전 존재하던 본 앱의 프로젝트 등록 검증이 변경 후에도 동일하게 통과한다.
- **SC-010**: Extension의 각 실패 경로(URL 판정 실패, 세션 없음·만료, 앱 실행 필요, 저장소 조회 실패, 등록 실패)가 기기 내 진단 로그로 구분 가능하며, 로그에 토큰·개인정보가 포함되지 않는다.

## 가정

- 프로젝트 등록은 기존 `CreateLearningProject` 흐름과 동일한 요청 규격을 사용하며 서버 변경은 없다.
- 등록 요청은 사용자가 Extension에 머무는 동안 응답을 받는 것을 전제로 하며, 장시간 백그라운드 작업을 두지 않는다.
- 공유 저장소로의 세션 이전은 본 앱이 담당하며 본 앱 최초 실행 시점에 이루어진다. Extension은 이전 작업을 수행하지 않고 이전 여부만 판정한다.
- 등록 가능 상태의 저장소 정보와 난이도 선택지는 본 앱의 저장소 확인·난이도 선택 화면과 동일한 데이터와 선택지를 사용한다.
- 퀴즈 생성 리마인더는 기존 `RequestGenerationReminder`의 권한 조회 경로를 사용해 허용 여부만 확인하며, Extension에서는 권한 요청 경로를 호출하지 않는다.
- 로그인 안내 상태는 안내 문구만 제공하며 Extension 안에서 로그인 화면을 제공하지 않는다.
- 지원 대상 호스트는 GitHub 한 곳이며 GitHub Enterprise 등 자체 호스팅 인스턴스는 범위 밖이다.
- 디자인 시스템과 등록·세션 확인 로직은 본 앱과 Extension이 함께 링크할 수 있는 단위로 제공되며, 그 분리 단위는 계획 단계에서 결정한다.
- 원본 요청의 SH-3(네트워크 호출 없는 검증)은 URL 형식 판정에만 적용하며, 판정 통과 후의 저장소 정보 조회는 본 앱과 동일하게 네트워크를 사용한다.
- 이 브랜치에서 이전에 시도한 공유 링크 전달 방식(본 앱으로 넘기는 컨테이너 기반 구현)은 이 명세의 범위에서 대체된다.

## 범위 밖

- 본 앱 실행 및 특정 화면 랜딩
- Extension 내 로그인·회원가입 플로우
- Extension 내 토큰 갱신
- GitHub 외 저장소 호스트 지원
- 등록 결과 상세 조회 및 퀴즈 생성 진행 상황 표시
- Extension 내 알림 권한 요청
- 실패한 등록 요청의 큐잉과 자동 재실행
