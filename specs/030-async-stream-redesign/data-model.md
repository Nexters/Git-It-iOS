# 데이터 모델: 생성 상태 관측 단일화와 무효 스트림 제거

**날짜**: 2026-09-15 | **명세**: [spec.md](./spec.md) | **조사**: [research.md](./research.md)

## 1. 생성 기록

생성 요청 하나의 수명을 나타내는 값이다. 등록 요청 시점에는 저장소 URL만 있고, 등록 응답을 받은 뒤 프로젝트 식별자가 부여된다.

| 속성 | 의미 | 제약 |
| --- | --- | --- |
| 정규화한 저장소 URL | 중복 등록 판정 키 | 공백 제거, 소문자화, 후행 `/` 제거. 비어 있을 수 없다 |
| 프로젝트 식별자 | 등록 응답으로 부여되는 식별자 | 등록 응답 전에는 없음 |
| 요청 시각 | 생성 요청을 보낸 시각 | 대기 시간과 만료 판정의 기준 |
| 상태 | 진행 중 / 완료 / 실패 | 진행 중에서만 완료 또는 실패로 전이한다 |
| 종료 시각 | 완료 또는 실패로 전이한 시각 | 진행 중에는 없음 |

**상태 전이**

```text
(없음) --요청--> 진행 중 --완료 통지--> 완료 --보존 한도 경과--> (제거)
                    |  --실패 통지--> 실패 --보존 한도 경과--> (제거)
                    |  --등록 실패--> (제거)
                    |  --만료--> (제거)
```

- 진행 중 기록은 요청 시각으로부터 보존 한도를 넘기면 제거한다. 기존 만료 기준을 그대로 사용한다.
- 완료·실패 기록은 종료 시각으로부터 보존 한도 동안 보관한다. 관측을 늦게 시작한 관측자가 종료 사실을 볼 수 있어야 하기 때문이다.
- 같은 정규화 URL에 대해 진행 중 기록은 최대 1개만 존재한다.

## 2. 생성 상태

특정 시점의 생성 기록 전체를 담는 스냅샷이다. 관측 대상이 전달하는 값이며 로컬에 보존되는 정본이다.

| 속성 | 의미 |
| --- | --- |
| 기록 목록 | 만료되지 않은 생성 기록 전체 |

**조회 규칙**

- 특정 저장소 URL이 진행 중인지: 해당 정규화 URL의 진행 중 기록 존재 여부.
- 진행 중인 프로젝트 식별자 집합: 프로젝트 식별자가 부여된 진행 중 기록의 식별자.
- 특정 프로젝트의 기록: 프로젝트 식별자가 일치하는 기록. 완료·실패 기록도 포함한다.

**불변식**

- 같은 프로젝트 식별자를 가진 기록은 최대 1개다.
- 같은 정규화 URL을 가진 진행 중 기록은 최대 1개다.
- 조회 시점에 만료된 기록은 스냅샷에 포함하지 않는다.

## 3. 자격 증명 상태

기존 Domain 값을 그대로 사용한다. 새 속성을 추가하지 않는다.

| 값 | 의미 | 세션 처리 |
| --- | --- | --- |
| 인증됨 | 플랫폼 자격 증명이 유효 | 변경 없음 |
| 재인증 필요 | 자격 증명이 취소·이전·부재 | 저장된 세션과 자격 증명 정보를 정리 |
| 일시적 확인 불가 | 상태를 확인할 수 없음 | 변경 없음 |

## 4. 대체되는 기존 모델

| 기존 | 처리 |
| --- | --- |
| 진행 정보(프로젝트 식별자 + 요청 시각) | 생성 기록의 부분 집합으로 흡수 |
| 등록 상태(정규화 URL + 요청 시각 + 프로젝트 식별자) | 생성 기록으로 흡수 |
| 생성 결과(프로젝트 식별자 + 완료·실패) | 생성 기록의 상태 전이 입력으로만 사용. 별도 영속 없음 |
| 인증 결과(인증됨 + 사용자 / 미인증 / 복구 가능 실패) | 제거. 자격 증명 상태로 대체 |

## 5. 영속과 이관

- 생성 상태는 앱과 공유 확장이 함께 읽는 로컬 저장소에 단일 키로 보존한다.
- 최초 로드 시 기존 두 키의 값을 읽어 생성 기록으로 병합하고 새 키에 저장한 뒤 기존 키를 제거한다. 이 이관은 1회만 수행한다.
- 병합 규칙: 기존 진행 정보는 프로젝트 식별자와 요청 시각을 가지므로 정규화 URL이 없다. 이 경우 URL이 비어 있는 기록으로 만들지 않고, 프로젝트 식별자를 가진 진행 중 기록으로 보존한다. 같은 프로젝트 식별자가 기존 등록 상태에도 있으면 등록 상태의 URL을 채택한다.
- 대기 시간 정책과 보존 한도의 값은 변경하지 않는다.
