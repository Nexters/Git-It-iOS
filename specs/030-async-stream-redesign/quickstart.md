# 빠른 시작: 생성 상태 관측 단일화와 무효 스트림 제거

**날짜**: 2026-09-15 | **명세**: [spec.md](./spec.md) | **계약**: [contracts/README.md](./contracts/README.md)

이 문서는 구현 결과를 검증하는 실행 절차를 기술한다. 구현 코드는 포함하지 않는다.

## 사전 조건

- workspace가 생성되어 있어야 한다. 없으면 `sources`에서 `tuist generate`를 먼저 실행한다.
- manifest(`sources/Tuist/ProjectDescriptionHelpers/**`)를 변경한 단위 뒤에는 workspace를 다시 생성한다.

```sh
make tuist
```

## 검증 명령

```sh
project_build_runner=$(./tools/repository-paths/bin/repository-paths.sh GIT_IT_PROJECT_BUILD_RUNNER)
"$project_build_runner" build     # 모든 공유 scheme Debug 빌드
"$project_build_runner" compile   # 테스트 scheme build-for-testing
"$project_build_runner" test      # test-without-building
```

세 명령은 `sources/DerivedData/PreCommit`을 공유하므로 순차 실행한다.

## 시나리오별 검증

### 시나리오 1 — 구독 시점과 무관한 생성 상태 관측

자동화 테스트로 검증한다. 다음 네 가지가 모두 통과해야 한다.

| 검증 | 확인 내용 |
| --- | --- |
| 늦은 관측 | 완료 통지를 먼저 전달한 뒤 관측을 시작하면 첫 값이 완료 상태다 |
| 이른 관측 | 관측을 먼저 시작하면 첫 값이 진행 중 상태이고 이어서 완료 상태를 받는다 |
| 다중 관측 | 관측자 둘이 같은 시점에 같은 상태를 받는다 |
| 순서 비의존 | 생성 요청 전에 미리 관측을 시작하지 않아도 결과를 받는다 |

수동 확인:

1. 프로젝트를 등록하고 진행 화면이 뜨기 전에 생성 완료 푸시가 도착하도록 만든다.
2. 진행 화면이 완료를 반영하는지 확인한다.
3. 홈 화면을 벗어난 상태에서 완료 푸시를 받고 홈에 다시 진입해 목록이 갱신되는지 확인한다.

### 시나리오 2 — 자격 증명 확인

| 검증 | 확인 내용 |
| --- | --- |
| 재인증 필요 | 세션과 자격 증명 정보가 정리되고 화면이 온보딩으로 돌아간다 |
| 인증됨 | 세션이 유지되고 화면 흐름이 바뀌지 않는다 |
| 확인 불가 | 세션을 정리하지 않는다 |

수동 확인: 설정에서 Apple 계정의 앱 사용을 중단한 뒤 앱을 다시 활성화해 온보딩으로 돌아가는지 확인한다.

### 시나리오 3 — 기기 토큰 갱신

| 검증 | 확인 내용 |
| --- | --- |
| 갱신 통지 | 갱신이 통지되면 기기 재등록이 수행된다 |
| 필수 주입 | 통지 수단을 주입하지 않으면 컴파일이 실패한다 |

두 번째 항목은 테스트가 아니라 빌드로 확인한다. 기본값이 남아 있으면 컴파일이 성공하므로 요구를 충족하지 못한 것이다.

### 예외·경계 사례

| 검증 | 확인 내용 |
| --- | --- |
| 즉시 취소 | 관측 시작 직후 취소하면 이후 값 전달 대상에서 제외된다 |
| 반복 등록·해제 | 관측을 반복 등록·해제해도 내부 관측자 목록 크기가 증가하지 않는다 |
| 만료 | 보존 한도를 넘긴 기록이 상태 스냅샷에서 제외된다 |
| 재실행 복원 | 앱을 다시 실행해도 진행 중 기록이 복원된다 |
| 기존 값 이관 | 기존 두 키에 값이 있는 상태에서 처음 불러오면 병합되어 새 키에 저장되고 기존 키가 제거된다 |
| 계정 삭제 | 로컬 상태 초기화 시 생성 기록이 비워진다 |

## 회귀 확인

변경 전후로 동일하게 동작해야 하는 흐름이다. 세 흐름 모두 수동으로 확인한다.

1. 프로젝트 등록 — 중복 URL 등록이 거부되고, 등록 중 항목이 목록에서 숨겨진다.
2. 홈 목록 갱신 — 생성 완료 후 목록에 항목이 나타난다.
3. 생성 완료 리마인드 알림 — 리마인드를 등록한 프로젝트의 생성이 완료되면 알림이 예약된다.

## 완료 판정

- 위 자동화 검증이 모두 통과한다.
- `build`, `compile`, `test` 세 명령이 성공한다.
- 변경 전 인증·생성 흐름 테스트의 보장 항목 수가 줄지 않았음을 대조표로 확인한다.
