## 변경 시나리오와 테스트 *(필수)*

### 시나리오 1 - 마이페이지에서 내 프로필과 학습 통계 확인 (우선순위: P1)

로그인한 사용자가 하단 탭의 "마이" 탭을 선택하면, 현재 자리표시자 화면 대신 이름·이메일과
직군·연차 배지, 학습 통계(이번 주 문제 수, 이번 달 문제 수, 연속 학습일, 주간 문제 풀이
추이)를 보여주는 프로필 화면이 표시된다.

**주요 행위자**: 최종 사용자 (로그인한 앱 사용자)

**우선순위 이유**: 마이 탭이 현재 자리표시자 화면([MainShellRouter.swift](../../sources/Projects/Feature/MainShell/Router/MainShellRouter.swift)의 `Self.PlaceholderView`)이라 사용자가 자신의 학습 현황과 계정 정보를 확인할 방법이 없다. 이 화면이 없으면 프로필·통계·설정 진입 전체가 앱에서 접근 불가능하므로 가장 먼저 구현해야 한다.

**독립 테스트**: 로그인 상태에서 "마이" 탭으로 이동해 이름·이메일·직군·연차 배지와 이번 주/이번 달/연속 학습·주간 추이가 실제 서버 데이터로 표시되는지 확인하는 것으로 전체를 검증할 수 있고, 사용자가 자신의 학습 현황을 스스로 파악할 수 있는 가치를 제공한다.

**수용 시나리오**:

1. **전제** 사용자가 로그인되어 있고 프로필 조회가 성공한 상태, **실행** "마이" 탭을 선택, **결과** 이름·이메일·직군 배지·연차 배지와 이번 주/이번 달 문제 수, 연속 학습일, 주간 풀이 추이가 화면에 표시된다.
2. **전제** 사용자가 "마이" 탭에 있고 프로필 조회가 진행 중인 상태, **실행** 화면 진입 직후, **결과** 로딩 상태를 사용자에게 알 수 있게 표시하고 이전 데이터나 빈 화면을 확정된 정보인 것처럼 보여주지 않는다.
3. **전제** 사용자가 "마이" 탭에 있고 프로필 조회가 실패한 상태(네트워크 오류 등), **실행** 화면 진입 또는 재시도, **결과** 재시도 가능한 오류 메시지를 표시하고 사용자가 재시도를 시도할 수 있다.
4. **전제** 프로필 화면이 표시된 상태, **실행** 우측 상단 설정 아이콘을 탭, **결과** 설정 화면으로 이동한다.

### 시나리오 2 - 직군·연차 변경 (우선순위: P2)

사용자가 설정 화면에서 자신의 직군(iOS/Android/Backend/Frontend)과 연차(입문/주니어/미들/시니어)를 각각 전체 화면 선택지에서 변경하면, 변경 사항이 즉시 반영되고 서버에 저장된다.

**주요 행위자**: 최종 사용자

**우선순위 이유**: 직군·연차는 학습 콘텐츠 추천과 관련된 개인화 정보이며 시나리오 1(조회)이 있어야 의미가 있는 후속 기능이다. 이미 [SettingsFeature](../../sources/Projects/Feature/Settings/Settings/SettingsFeature.swift)에 `positionSelected`/`careerLevelSelected` 동작과 실패 처리 로직이 구현되어 있어 화면만 연결하면 되므로 우선순위가 높다.

**독립 테스트**: 설정 화면에서 "개발 분야"/"개발 수준" 행을 눌러 선택 화면으로 이동한 뒤 다른 값을 선택했을 때 설정 화면에 즉시 반영되고, 앱을 재시작하거나 화면을 다시 방문해도 변경 값이 유지되는지 확인하는 것으로 검증할 수 있고, 사용자가 자신의 정보를 최신 상태로 유지할 수 있는 가치를 제공한다.

**수용 시나리오**:

1. **전제** 설정 화면에서 "개발 분야" 행을 탭한 상태, **실행** 개발 분야 선택 화면에서 옵션 중 하나를 선택, **결과** 설정 화면으로 돌아오면 선택한 직군이 즉시 반영되고 서버 저장이 완료된다.
2. **전제** 설정 화면에서 "개발 수준" 행을 탭한 상태, **실행** 개발 수준 선택 화면에서 옵션 중 하나를 선택, **결과** 설정 화면으로 돌아오면 선택한 연차가 즉시 반영되고 서버 저장이 완료된다.
3. **전제** 직군 또는 연차 변경 요청이 서버 오류로 실패한 상태, **실행** 변경 실패 발생, **결과** 변경 전 값을 그대로 유지하며 재시도 가능한 오류 문구를 표시해 사용자가 실패를 인지할 수 있다.

### 시나리오 3 - 로그아웃과 계정 탈퇴 (우선순위: P3)

사용자가 설정 화면에서 로그아웃하거나, 별도의 확인 화면을 거쳐 계정을 탈퇴할 수 있다.

**주요 행위자**: 최종 사용자

**우선순위 이유**: 계정 관리는 필수 기능이지만 조회·개인화(시나리오 1, 2)보다 사용 빈도가 낮고, 탈퇴는 파괴적 동작이라 별도 확인 절차가 필요해 마지막 우선순위로 둔다. [SettingsFeature](../../sources/Projects/Feature/Settings/Settings/SettingsFeature.swift)에 `signOutTapped`/`deleteAccountTapped`/`deleteAccountConfirmed` 흐름이 이미 구현되어 있다.

**독립 테스트**: 설정 화면에서 로그아웃 버튼을 눌러 로그인 화면으로 돌아가는지, "계정 삭제" 행을 눌러 확인 화면으로 이동하고 확정 시 계정이 삭제되어 로그인 화면으로 돌아가는지 확인하는 것으로 검증할 수 있고, 사용자가 자신의 계정 상태를 스스로 제어할 수 있는 가치를 제공한다.

**수용 시나리오**:

1. **전제** 사용자가 설정 화면에 있는 상태, **실행** 로그아웃 버튼 탭, **결과** 세션이 종료되고 로그인 화면으로 이동한다.
2. **전제** 사용자가 설정 화면에 있는 상태, **실행** "계정 삭제" 행 탭, **결과** 탈퇴 안내와 확정 버튼이 있는 별도 확인 화면으로 이동하고, 뒤로가기 시 설정 화면으로 돌아가며 계정에 변화가 없다.
3. **전제** 계정 삭제 확인 화면이 표시된 상태, **실행** "회원 탈퇴" 버튼 탭, **결과** 계정이 삭제되고 로그인 화면으로 이동한다.

### 시나리오 4 - 설정 화면에서 이용약관 확인 (우선순위: P4)

사용자가 설정 화면에서 "서비스 약관 및 정책" 행을 눌러 약관·개인정보 내용을 확인할 수 있다.

**주요 행위자**: 최종 사용자

**우선순위 이유**: 법적·정책 고지이며 앞선 세 시나리오보다 사용 빈도와 개발 의존성이 낮다. 기존 UseCase만으로 표현 가능한 정적 콘텐츠라 이번 범위에 포함하되 우선순위는 가장 낮다.

**독립 테스트**: 설정 화면에서 해당 행을 눌러 약관·개인정보 내용(또는 외부 링크)이 표시되는지 확인하는 것으로 검증할 수 있고, 사용자가 서비스 이용 조건을 확인할 수 있는 가치를 제공한다.

**수용 시나리오**:

1. **전제** 사용자가 설정 화면에 있는 상태, **실행** "서비스 약관 및 정책" 행 탭, **결과** 약관·개인정보 내용을 확인할 수 있는 화면(또는 외부 링크)으로 이동한다.

### 예외·경계 사례

- 프로필의 직군 또는 연차가 아직 설정되지 않은(`nil`) 상태일 때, 설정 화면은 해당 행에 "선택 안 함" placeholder 문구를 표시하고 탭하면 선택 화면이 열린다.
- 학습 통계가 모두 0인 신규 사용자일 때 통계 영역은 오류가 아닌 "0" 값의 정상 상태로 표시된다.
- 로그아웃 또는 계정 탈퇴 처리 중 사용자가 화면을 벗어나거나 앱을 백그라운드로 전환하면 어떻게 되는가?
- 직군·연차 변경 요청이 진행 중일 때 동일 항목을 다시 선택하면 중복 요청이 발생하지 않는가?
- 프로필 화면과 설정 화면 사이를 반복 왕복해도 각 화면의 조회 상태가 불필요하게 재조회되지 않는가(화면별 로드 정책은 계획 단계에서 확정).

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 하단 탭의 "마이" 탭 선택 시 기존 자리표시자 화면 대신 프로필 화면을 표시해야 한다.
- **FR-002**: 시스템은 프로필 화면 진입 시 로그인한 사용자의 프로필(이름, 이메일, 직군, 연차)과 학습 통계(이번 주 문제 수, 이번 달 문제 수, 연속 학습일, 주간 풀이 추이)를 조회해 표시해야 한다.
- **FR-003**: 시스템은 프로필 조회가 진행 중인 동안 로딩 상태를 사용자에게 알 수 있게 표시해야 한다.
- **FR-004**: 시스템은 프로필 조회가 실패하면 재시도 가능한 오류 상태를 표시해야 한다.
- **FR-004a**: 사용자는 프로필 화면의 설정 아이콘을 탭해 설정 화면으로 이동할 수 있어야 한다.
- **FR-005**: 사용자는 설정 화면에서 자신의 직군을 iOS/Android/Backend/Frontend 중에서, 전체 화면 선택지를 통해 변경할 수 있어야 한다.
- **FR-006**: 사용자는 설정 화면에서 자신의 연차를 입문/주니어/미들/시니어 중에서, 전체 화면 선택지를 통해 변경할 수 있어야 한다.
- **FR-006a**: 시스템은 직군 또는 연차가 미설정(`nil`)일 때 설정 화면의 해당 행에 "선택 안 함" placeholder 문구를 표시해야 하며, 사용자가 그 행을 탭하면 선택 화면이 열려야 한다.
- **FR-007**: 시스템은 직군 또는 연차 변경이 서버 저장에 실패하면 변경 전 값을 그대로 유지하며, 동시에 재시도 가능한 오류 문구를 표시해 사용자가 실패를 인지하게 해야 한다.
- **FR-008**: 사용자는 설정 화면에서 로그아웃할 수 있어야 하며, 로그아웃이 완료되면 로그인 화면으로 이동해야 한다.
- **FR-009**: 사용자는 설정 화면에서 "계정 삭제" 행을 눌러 별도의 확인 화면으로 이동할 수 있어야 하며, 그 화면에서 확정해야만 실제 삭제가 진행되어야 한다.
- **FR-010**: 시스템은 계정 삭제가 확정되면 계정을 삭제하고 로그인 화면으로 이동해야 한다.
- **FR-011**: 시스템은 직군 또는 연차 변경 요청이 진행 중인 동안 동일 항목에 대한 중복 요청을 막아야 한다.
- **FR-012**: 프로필·설정·개발 분야 선택·개발 수준 선택·계정 삭제 확인 화면의 레이아웃, 색상, 타이포그래피, 컴포넌트 구성은 [Figma 디자인](https://www.figma.com/design/mCRt0ejmzI4EFW3UnC9Bzb/%EB%84%A5%ED%84%B0-Git-it--MCP--cncnfdyd)의 해당 노드(`1539:19209` 외 2개, `1465:19689`, `1535:18281`, `1535:18378`, `1636:31714`)를 근거로 구현해야 한다.
- **FR-013**: 사용자는 설정 화면에서 "서비스 약관 및 정책" 행을 눌러 약관·개인정보 내용을 확인할 수 있어야 한다.
- **FR-014**: "세트 생성 완료 알림"(알림 설정) 항목은 이번 기능 범위에서 제외한다. 설정 화면에는 다른 항목만 구현하며, 알림 설정 항목이 필요한 새 Domain 조사와 구현은 별도 명세로 다룬다.

### 핵심 엔터티

- **MemberProfile**: 사용자의 이름, 이메일, 직군(`MemberPosition?`), 연차(`CareerLevel?`), 학습 통계(`LearningStatistics`)를 표현하는 기존 도메인 모델. (참고: [MemberProfile.swift](../../sources/Projects/Domain/Member/Models/MemberProfile/MemberProfile.swift))
- **LearningStatistics**: 이번 주 문제 수(`thisWeekSolvedCount`), 이번 달 문제 수(`thisMonthSolvedCount`), 연속 학습일(`streakDays`), 요일별 풀이 추이(`weeklyCounts`)를 표현하는 기존 도메인 모델. 서버 `GET /api/v1/members/me` 응답과 일치하도록 필드를 교정한다(가정 참고). (참고: [LearningStatistics.swift](../../sources/Projects/Domain/Member/Models/MemberProfile/LearningStatistics.swift))

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 로그인한 사용자가 "마이" 탭을 선택하면 자리표시자 없이 실제 프로필 정보가 포함된 화면이 표시된다.
- **SC-002**: 정상 응답 조건에서 프로필과 학습 통계 데이터(이번 주/이번 달/연속 학습/주간 추이)가 로딩 상태 없이 최종적으로 화면에 표시된다.
- **SC-003**: 직군 또는 연차 변경 시도의 100%가 성공(반영 및 저장) 또는 명확한 실패 안내로 종결되며, 사용자가 결과를 알 수 없는 상태로 남지 않는다.
- **SC-004**: 계정 삭제는 확인 화면을 거치지 않고 즉시 실행되는 경우가 0%이다.
- **SC-005**: 프로필·설정·개발 분야 선택·개발 수준 선택·계정 삭제 확인 5개 화면 구현이 각각 대응하는 Figma 노드의 레이아웃·타이포그래피·색상 명세와 일치한다.

## 가정

- 설정 화면의 계정 관리 기능(직군·연차 변경, 로그아웃, 계정 삭제)은 이미 구현된 [SettingsFeature](../../sources/Projects/Feature/Settings/Settings/SettingsFeature.swift)의 State·Action·Reducer를 재사용한다. 프로필 화면은 신규 Feature(예: `ProfileFeature`)가 필요하며, 두 화면을 연결하는 Router도 신규로 필요하다 — [TCA Navigation 컨벤션 §2.3](../../docs/conventions/tca/navigation.md#23-router-feature와-화면-전환-소유)의 순차 흐름 패턴을 따른다.
- `LearningStatistics`의 필드를 서버 실측 응답(`thisWeekSolvedCount`/`thisMonthSolvedCount`/`streakDays`/`weeklyChart`)에 맞게 교정하는 것은 새 서버 계약을 요구하지 않는 기존 데이터 흐름의 버그 수정이며, Domain과 Composition(`MemberRepositoryAdapter`) 패키지가 이번 기능의 적용 대상에 포함된다.
- 개발 분야·개발 수준 선택 화면은 온보딩의 [CareerSelectionScreen](../../sources/Projects/Feature/Onboarding/CareerSelection/CareerSelectionScreen.swift)·[PositionSelectionScreen](../../sources/Projects/Feature/Onboarding/PositionSelection/PositionSelectionScreen.swift)과 동일한 `SelectionCardList` 기반 시각 패턴을 참고하되, 설정 흐름 전용 화면으로 별도 구현한다(온보딩 화면을 직접 재사용하지 않는다).
- 인증되지 않은 사용자는 마이 탭에 접근하기 전에 이미 로그인 절차를 거친 상태라고 가정한다 (기존 온보딩/로그인 플로우 재사용).
- 계정 삭제 확인은 앱 내 별도 화면으로 처리하며, 추가 재인증(비밀번호 재입력 등)은 요구하지 않는다.
- "세트 생성 완료 알림" 설정 항목은 이번 범위에서 제외하고 후속 기능으로 분리한다(FR-014).
