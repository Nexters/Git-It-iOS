# 기능 명세: 비로그인(게스트) 모드

**Git-flow 유형**: `feature`

**기능 브랜치**: `feature/guest-mode`

**브랜치 상태**: `생성`

**생성일**: 2026-09-19

**상태**: 초안

**입력**: 사용자 설명: "비로그인을 지원해야합니다. 비로그인 모드 — 인증 세션이 필요한 파트 비활성화(로그인 요청 알럿 액션 or 안내 메세지): 홈(프로필 섹션 → 로그인 섹션, 프로젝트 생성 → 시스템 알럿으로 로그인 필요 안내, 프로젝트 카드 리스트 → 로그인 필요 안내, 전체보기 비활성), 프로젝트 목록 탭 비활성, 저장한 문제 탭 비활성, 마이페이지 → 로그인 화면"

## 배경

App Store 심사에서 지침 5.1.1(v)(계정 기반이 아닌 기능에 로그인을 요구하지 말 것) 지적을 받았다
([이의제기 문안](../../docs/release/guideline-5-1-1-appeal.md)). 현재 앱은 튜토리얼 마지막 면의 Apple
로그인을 통과해야만 메인 화면에 들어갈 수 있다. 이 기능은 로그인하지 않은 사용자도 메인 화면에
들어와 앱의 구성을 확인할 수 있게 하고, 계정이 필요한 기능은 비활성화하거나 로그인을 안내한다.

## 명확화

### 세션 2026-09-19

- 질문: 비로그인 상태에서 로그인한 뒤 약관 동의나 직군·연차 입력을 중단하면 어디로 가는가? → 답변: 로그아웃한 뒤 비로그인 메인 화면으로 돌아간다
  (분석 반영: 약관 동의는 로그인 전에 진행되므로, 약관 취소는 로그아웃 없이 비로그인 메인을 유지하고 직군·연차 중단만 로그아웃한다 — FR-012)
- 질문: 로그인 사용자가 로그아웃하거나 계정을 삭제하면 어디로 가는가? → 답변: 기존과 같이 온보딩 튜토리얼 첫 면으로 돌아간다(비로그인 메인 화면으로 보내지 않음)
- 질문: 비로그인 상태에서 로그인에 성공한 직후 어느 탭을 표시하는가? → 답변: 로그인을 시작한 탭을 유지한다(홈은 홈, 마이는 프로필로 전환)

## 변경 시나리오와 테스트 *(필수)*

### 시나리오 1 - 로그인 없이 메인 화면 진입 (우선순위: P1)

로그인하지 않은 사용자가 온보딩에서 로그인 대신 비로그인 진입을 선택해 메인 화면(홈 탭)에 들어간다.
진입 과정에서 약관 동의, 직군·연차 선택 같은 계정 전제 단계를 요구하지 않는다.

**주요 행위자**: 로그인하지 않은 최종 사용자, App Store 심사자

**우선순위 이유**: 심사 지적을 해소하는 최소 단위다. 이 시나리오만으로도 로그인 없이 앱을 둘러볼 수 있다.

**독립 테스트**: 로그인 기록이 없는 상태에서 앱을 실행하고 비로그인 진입을 선택하면 로그인·약관·직군 입력
없이 홈 탭이 표시되는지 확인한다.

**수용 시나리오**:

1. **전제** 로그인 기록이 없는 첫 실행, **실행** 튜토리얼 마지막 면에서 Apple 로그인 아래의 비로그인 진입
   선택, **결과** 약관·직군·연차 화면 없이 홈 탭이 선택된 메인 화면이 표시된다.
2. **전제** 비로그인 상태로 메인 화면 진입, **실행** 화면 표시, **결과** 계정 전용 데이터(프로젝트, 저장한
   문제, 프로필, 학습 통계) 요청이 한 건도 발생하지 않는다.
3. **전제** 비로그인 상태, **실행** 앱이 백그라운드에서 다시 활성화됨, **결과** 재인증 요구로 판단해
   온보딩으로 되돌리지 않고 비로그인 메인 화면을 유지한다.
4. **전제** 비로그인 메인 화면을 사용하던 중 앱 종료, **실행** 앱 재실행, **결과** 메인 화면이 아니라
   온보딩 튜토리얼 첫 면이 표시된다.

---

### 시나리오 2 - 홈 화면의 계정 기능 대체 표시 (우선순위: P1)

비로그인 사용자가 홈 탭을 보면 계정이 필요한 영역이 로그인 안내로 바뀌어 있고, 계정이 필요한 동작을
시도하면 로그인이 필요하다는 안내를 받는다.

**주요 행위자**: 로그인하지 않은 최종 사용자

**우선순위 이유**: 진입 직후 가장 먼저 보이는 화면이며, 빈 화면이나 오류 대신 명확한 안내를 줘야 한다.

**독립 테스트**: 비로그인 홈 탭에서 각 영역의 표시와 탭 반응을 확인한다.

**수용 시나리오**:

1. **전제** 비로그인 홈, **실행** 화면 표시, **결과** 프로필 섹션 자리에 로그인을 유도하는 로그인 섹션이
   표시된다.
2. **전제** 비로그인 홈, **실행** 로그인 섹션의 로그인 동작 선택, **결과** 로그인 흐름(FR-011)이 시작된다.
3. **전제** 비로그인 홈, **실행** 프로젝트 생성 동작 선택, **결과** 프로젝트 등록 화면을 열지 않고 로그인이
   필요하다는 시스템 알럿이 표시된다. 알럿에는 로그인으로 이어지는 동작과 닫기 동작이 있다.
4. **전제** 비로그인 홈, **실행** 화면 표시, **결과** 프로젝트 카드 목록 자리에 로그인이 필요하다는 안내
   문구가 표시되고 프로젝트 카드는 표시되지 않는다.
5. **전제** 비로그인 홈, **실행** 전체보기 선택 시도, **결과** 전체보기는 비활성 상태로 표시되며 선택해도
   프로젝트 탭으로 이동하지 않는다.

---

### 시나리오 3 - 계정 전용 탭 제한 (우선순위: P1)

비로그인 사용자는 프로젝트 목록 탭과 저장한 문제 탭을 선택할 수 없고, 마이 탭에서는 프로필 대신 로그인
화면을 본다.

**주요 행위자**: 로그인하지 않은 최종 사용자

**우선순위 이유**: 계정 없이는 의미 있는 내용이 없는 탭에서 빈 화면이나 요청 실패가 노출되지 않아야 한다.

**독립 테스트**: 비로그인 메인 화면에서 각 탭을 선택해 반응을 확인한다.

**수용 시나리오**:

1. **전제** 비로그인 메인 화면, **실행** 프로젝트 탭 선택, **결과** 탭은 비활성으로 표시되고 선택 탭이
   바뀌지 않으며 프로젝트 목록 요청이 발생하지 않는다.
2. **전제** 비로그인 메인 화면, **실행** 저장 탭 선택, **결과** 탭은 비활성으로 표시되고 선택 탭이 바뀌지
   않으며 저장한 문제 요청이 발생하지 않는다.
3. **전제** 비로그인 메인 화면, **실행** 마이 탭 선택, **결과** 프로필·학습 현황·설정 대신 로그인 화면이
   표시되고, 그 화면에서 로그인 흐름(FR-011)을 시작할 수 있다.

---

### 시나리오 4 - 비로그인 상태에서 로그인으로 전환 (우선순위: P2)

비로그인 사용자가 안내를 따라 로그인하면, 신규 계정에 필요한 온보딩 단계를 마친 뒤 모든 기능이 활성화된
메인 화면으로 돌아온다.

**주요 행위자**: 로그인하지 않은 최종 사용자

**우선순위 이유**: 비로그인 모드가 막다른 길이 되지 않도록 전환 경로를 보장한다. P1 없이도 기존 온보딩
로그인은 동작하므로 P2로 둔다.

**독립 테스트**: 비로그인 상태의 각 로그인 진입점에서 로그인을 완료하고 전 기능이 활성화되는지 확인한다.

**수용 시나리오**:

1. **전제** 비로그인 메인 화면, 이 기기에 필수 약관 동의 기록이 있음, **실행** 로그인 진입점 선택, **결과**
   메인 화면을 유지한 채 Apple 로그인이 바로 시작된다. 동의 기록이 없으면 메인 화면 위에 약관 동의 화면이 먼저
   표시되고, 동의를 마치면 Apple 로그인이 시작된다.
2. **전제** 비로그인 메인 화면, **실행** 로그인 진입점에서 Apple 로그인 성공(추가 정보가 필요 없는 기존
   계정), **결과** 온보딩 화면을 거치지 않고 모든 탭과 홈 기능이 활성화된 메인 화면이 표시되며, 로그인을
   시작한 탭이 그대로 선택되어 있다(마이 탭에서 시작했다면 로그인 화면이 프로필로 바뀐다).
3. **전제** 비로그인 메인 화면, **실행** Apple 로그인 성공(직군·연차 입력이 필요한 계정), **결과** 직군·연차
   입력 단계를 거친 뒤 메인 화면으로 이동한다.
4. **전제** 비로그인 메인 화면에서 로그인 진입점을 선택해 약관 동의 화면이 표시됨, **실행** 약관 동의 취소,
   **결과** 로그인을 시작하지 않고 비로그인 메인 화면이 그대로 유지된다.
5. **전제** 비로그인 메인 화면에서 로그인해 직군·연차 입력 단계로 이동, **실행** 직군·연차 입력 중단,
   **결과** 로그아웃되고 튜토리얼이 아니라 비로그인 메인 화면으로 돌아간다.
6. **전제** 비로그인 메인 화면, **실행** Apple 로그인 취소 또는 실패, **결과** 비로그인 메인 화면이 그대로
   유지되고 재시도할 수 있다.

---

### 예외·경계 사례

- 로그인 사용자가 로그아웃하거나 계정을 삭제하면 비로그인 메인 화면이 아니라 기존과 같이 온보딩 튜토리얼 첫
  면으로 돌아간다. 로그인 사용자의
  세션이 만료되어 재인증이 필요할 때도 기존 동작을 유지한다.
- 비로그인 상태에서는 기기 푸시 토큰 등록 요청을 보내지 않는다(기기 등록은 계정에 귀속된다).
- 비로그인 상태에서 공유 확장으로 저장소 링크를 공유하면 기존 공유 확장의 "로그인이 필요해요" 안내가
  그대로 표시된다(이번 범위에서 변경하지 않음).
- 비로그인 상태로 앱을 종료한 뒤 다시 실행하면 비로그인 선택을 기억하지 않으므로 튜토리얼 첫 면부터
  시작한다(FR-003).
- 비로그인 로그인 진입점에서 로그인에 성공했으나 약관 동의나 직군·연차 입력 도중 앱을 종료하면, 다음 실행은
  기존 로그인 사용자 복원 규칙(필요한 온보딩 단계부터 재개)을 따른다.
- 로그인 흐름 진행 중 같은 로그인 동작을 반복 선택해도 로그인 요청은 한 번만 진행된다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 튜토리얼 마지막 면의 Apple 로그인 동작 아래에 로그인 없이 메인 화면으로 진입하는
  보조 동작을 제공해야 한다. 튜토리얼의 다른 면에는 비로그인 진입 동작을 두지 않는다.
- **FR-002**: 비로그인 진입은 약관 동의, 직군·연차 선택을 요구하지 않아야 한다.
- **FR-003**: 시스템은 비로그인 선택을 기기에 저장하지 않아야 한다. 로그인 기록이 없는 상태로 앱을 다시
  실행하면 매번 온보딩 튜토리얼부터 표시한다.
- **FR-004**: 비로그인 상태의 메인 화면은 계정에 귀속된 데이터(프로젝트, 세트, 답안, 저장한 문제, 프로필,
  학습 통계)와 기기 등록 요청을 서버에 보내지 않아야 한다.
- **FR-005**: 비로그인 홈은 프로필 섹션 대신 로그인 섹션을 표시하고, 로그인 섹션에서 로그인 흐름을 시작할 수
  있어야 한다.
- **FR-006**: 비로그인 홈에서 프로젝트 생성 동작을 선택하면 프로젝트 등록 화면을 열지 않고 로그인이 필요하다는
  시스템 알럿을 표시해야 한다. 알럿은 로그인 흐름을 시작하는 동작과 닫기 동작을 제공해야 한다.
- **FR-007**: 비로그인 홈은 프로젝트 카드 목록 대신 로그인이 필요하다는 안내 문구를 표시해야 한다.
- **FR-008**: 비로그인 홈의 전체보기는 비활성 상태로 표시되고 선택해도 탭을 바꾸지 않아야 한다.
- **FR-009**: 비로그인 메인 화면의 프로젝트 탭과 저장 탭은 비활성 상태로 표시되고 선택해도 선택 탭을 바꾸지
  않아야 한다.
- **FR-010**: 비로그인 상태에서 마이 탭을 선택하면 프로필·설정 대신 로그인 화면을 표시해야 한다.
- **FR-011**: 비로그인 상태의 로그인 진입점(홈 로그인 섹션, 프로젝트 생성 알럿, 마이 탭 로그인 화면)은
  메인 화면을 벗어나지 않고 그 자리에서 같은 Apple 로그인을 시작해야 한다. 튜토리얼 화면으로 이동하지 않는다.
- **FR-012**: 비로그인 상태의 로그인은 기존 온보딩과 같은 순서로 진행해야 한다: 약관 동의(이 기기에 필수 약관
  동의 기록이 없을 때만) → Apple 로그인 → 직군·연차 선택(계정에 필요할 때만). 모든 단계를 마치면 모든 기능이
  활성화된 메인 화면을 표시하며, 로그인을 시작한 탭을 선택한 상태여야 한다(직군·연차 단계를 거친 경우 포함).
  약관 동의를 취소하면 로그인을 시작하지 않고 비로그인 메인 화면을 유지하고, 직군·연차 선택을 중단하면
  로그아웃한 뒤 비로그인 메인 화면으로 돌아가야 한다.
- **FR-013**: 비로그인 상태에서 로그인이 취소되거나 실패하면 비로그인 메인 화면을 유지하고 재시도할 수 있어야
  한다.
- **FR-014**: 비로그인 상태에서는 앱 재활성화 시의 로그인 검증 결과로 온보딩으로 되돌리지 않아야 한다.
- **FR-015**: 로그인 사용자의 기존 동작(로그아웃·계정 삭제·재인증 요구 시 온보딩 복귀, 모든 탭과 홈 기능)은
  변경되지 않아야 한다.

### 핵심 엔터티

- **세션 모드**: 앱이 현재 로그인 사용자로 동작하는지, 비로그인 사용자로 동작하는지를 나타내는 상태. 메인
  화면의 각 영역은 이 상태에 따라 표시와 동작을 결정한다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 로그인 기록이 없는 사용자가 앱 실행 후 로그인·개인정보 입력 없이 2회 이하의 선택으로 홈 탭에
  도달한다. 튜토리얼 면을 넘기는 스와이프·페이지 이동은 선택 횟수에 포함하지 않는다.
- **SC-002**: 비로그인 상태에서 메인 화면의 모든 탭과 홈 동작을 한 번씩 수행하는 동안 계정 귀속 데이터 요청과
  기기 등록 요청이 0건이다.
- **SC-003**: 비로그인 상태에서 계정이 필요한 영역(홈 4개 영역, 탭 3개) 7곳 모두가 빈 화면·오류 화면 대신 안내,
  비활성 표시 또는 로그인 화면을 보여준다.
- **SC-004**: 비로그인 상태의 로그인 진입점 3곳 모두에서 로그인에 성공하면 모든 기능이 활성화된 메인 화면에
  도달한다.
- **SC-005**: 로그인 사용자 흐름에 대한 기존 자동 테스트가 변경 전후 동일하게 모두 통과한다.

## 가정

- 명세 작성 단계의 사용자 결정(2026-09-19, `명확화` 절의 Q1~Q3와 별개): 비로그인 진입은 튜토리얼 마지막 면
  보조 동작(FR-001), 비로그인 선택은 저장하지 않음(FR-003), 비로그인 상태 로그인은 메인 화면에서 바로 Apple
  로그인(FR-011). 이 문서와 하위 산출물의 "명확화 Q#"는 `명확화` 절의 세션 2026-09-19 질문 번호만 가리킨다.
- 비로그인 사용자에게 샘플 문제 풀이나 번들 콘텐츠는 제공하지 않는다. 계정 기능은 비활성화 또는 로그인
  안내로만 대체한다.
- 로그인 방식은 기존과 같이 Apple 로그인만 사용한다.
- 비활성 탭과 전체보기는 선택해도 별도 알럿 없이 반응하지 않으며, 비활성임을 시각적으로 구분한다.
- 로그인 섹션·로그인 화면·안내 문구·알럿의 구체 문구와 레이아웃은 Figma 노드가 있으면 그것을 따르고,
  없으면 계획 단계에서 정한다.
- 비로그인 상태에서 앱 알림 권한이나 생성 완료 알림은 다루지 않는다(프로젝트 생성이 불가능하므로).
- 공유 확장의 비로그인 동작은 이번 범위에서 변경하지 않는다.
