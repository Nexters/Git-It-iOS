## 검증 이력

### 1차 검증 (2026-08-14)

- 미해결 항목: `[NEEDS CLARIFICATION]` 2건
  - **FR-014** 본문 변환 범위: 본문을 바이트 그대로만 전달할지, 호출자가 지정한 형식으로 변환까지
    수행할지 결정되지 않음. 이 기능이 소유하는 책임의 크기와 경계 변환 담당자의 작업량이 함께
    달라지므로 기본값을 임의로 정하지 않았다.
  - **FR-015** 일시적 실패의 재시도 책임: 자동 재시도를 이 기능이 수행할지, 호출자가 결정할지
    정해지지 않음. 상위 경계에 "일시적 통신 실패 시 상태를 유지한 채 재시도" 요구가 이미
    존재하므로 책임 위치가 동작 결과를 바꾼다.
- 그 외 모든 항목은 통과했다.
- 조치: 두 항목을 사용자 질문으로 제시했다.

### 2차 검증 (2026-08-14)

- 사용자 결정
  - **FR-014**: 호출자가 지정한 형식으로 본문 변환까지 수행한다. 변환 대상 형식과 필드 표기 대응
    규칙은 호출자가 소유하며, 이 기능은 특정 서비스의 형식을 내부에 고정하지 않는다.
  - **FR-015**: 자동 재시도를 수행하지 않는다. 실패 원인만 전달하고 재시도 여부는 호출자가
    결정하며, 한 번의 호출은 최대 한 번만 서버로 전송한다.
- 결정에 따라 함께 갱신한 항목
  - FR-002, FR-011, FR-013: 본문 변환 책임을 반영
  - FR-004: 실패 원인을 5가지에서 6가지로 확장(요청 본문 변환 실패, 응답 본문 변환 실패 분리)
  - 사용자 스토리 1·2의 수용 시나리오, 예외·경계 사례, 범위 포함·제외, 핵심 엔터티
  - SC-002(6가지 실패 원인), SC-003(본문 변환 포함), SC-008(중복 전송 0건) 신설
- 결과: 16개 항목 전부 통과. `[NEEDS CLARIFICATION]` 잔여 0건.
