# 기능 명세: 서버 프로젝트 목록에서 확인된 생성 중 프로젝트를 완료로 반영

**Git-flow 유형**: `feature`

**기능 브랜치**: `feature/generation-list-completion`

**브랜치 상태**: `생성`

**생성일**: 2026-10-01

**상태**: 초안

**입력**: 사용자 설명: "생성 중으로 기록된 projectID가 서버 프로젝트 목록에서 확인되면 그 생성을 완료로 반영한다. 배경: 서버가 생성 결과 원격 알림(QUIZ_READY)을 보내지 않는 경우가 있어, 목록에는 프로젝트가 추가되었는데도 생성 기록이 진행 중으로 남아 홈 불러오기 잠금·생성 진행 화면·공유 확장 생성 중 차단(047)이 보관 기한(1시간)까지 풀리지 않는다. 지금은 프로젝트를 삭제하거나(046 FR-022의 release) 로그아웃해야만 풀린다. 결정(2026-10-01 사용자 확인): (1) 서버 프로젝트 목록에는 문제 생성이 끝난 프로젝트만 나타나므로, 목록 포함을 생성 완료의 근거로 삼는다. (2) 종료 방식은 기록 해제가 아니라 완료 전이다. 원격 알림 QUIZ_READY와 같은 결과로 반영해 진행 화면이 완료 흐름으로 넘어가고 홈 잠금과 공유 확장 차단이 풀린다. (3) 목록 항목(ProjectListItemDTO)에는 생성 상태 필드가 없으며, 새 서버 API·폴링은 추가하지 않고 기존 목록 로드(첫 페이지·새로고침·다음 페이지)의 결과만 사용한다(046 FR-020, 048 FR-009 유지). 048 가정 '생성 결과는 원격 알림으로만 들어온다, 원격 알림이 아닌 결과 경로가 생기면 그때 알림 방식을 다시 정한다'를 이 명세가 갱신해야 하며, 목록 경로로 완료를 반영할 때 사용자 알림을 어떻게 할지 정한다. 선행 관계: 048(feature/generation-outcome-payload, develop 미병합)의 로컬 결과 알림 제거와 payload 인식 위에서 동작하므로 048 브랜치를 기준으로 한다."

## 배경

앱은 생성 요청마다 공유 저장소에 생성 기록을 남기고, 서버의 생성 결과 원격 알림(048: `QUIZ_READY`·
`QUIZ_REJECTED`)으로 그 기록을 완료·실패로 바꾼다. 메인 앱의 홈 "지금 불러오기" 잠금, 생성 진행 화면,
공유 확장의 생성 중 등록 차단(047)이 모두 이 기록을 읽는다.

2026-10-01 실기기 관찰에서 서버가 생성 결과 원격 알림을 보내지 않는 경우가 있었다. 이때 서버 프로젝트
목록에는 새 프로젝트가 이미 나타나지만(046 목록 자동 갱신), 생성 기록은 진행 중으로 남는다. 기록이
풀리는 경로는 다음뿐이다.

- 보관 기한(요청 시각부터 1시간) 만료
- 로그아웃(모든 기록 해제)
- 그 프로젝트 삭제(046 FR-022: 삭제한 프로젝트의 생성 기록 해제)

그래서 사용자는 새 프로젝트를 목록에서 보면서도 최대 1시간 동안 다른 저장소를 등록할 수 없다. 프로젝트
삭제로 잠금이 풀리는 것은 정리 목적의 부수 효과이며 알림 누락의 복구 수단이 아니다.

서버 프로젝트 목록에는 문제 생성이 끝난 프로젝트만 나타난다(2026-10-01 사용자 확인). 따라서 목록에
포함된 프로젝트는 생성이 완료된 것으로 판단할 수 있다.

## 명확화

### 세션 2026-10-01

- 질문: 서버 프로젝트 목록에는 어느 시점부터 새 프로젝트가 나타나는가? → 답변: 문제 생성이 끝난 뒤에만
  나타난다. 목록 포함을 생성 완료의 근거로 삼는다.
- 질문: 목록에서 확인된 생성 중 기록을 어떤 상태로 끝내는가? → 답변: 기록 해제가 아니라 완료로 전이한다.
  원격 알림 `QUIZ_READY`와 같은 결과로 반영한다.
- 질문: 이 변경을 어떤 절차로 진행하는가? → 답변: 048과 분리한 새 명세로 진행하고, 048 브랜치를 기준으로
  한다.

## 변경 시나리오와 테스트 *(필수)*

### 시나리오 1 - 결과 알림 없이 목록에 나타난 프로젝트로 생성 중 해제 (우선순위: P1)

서버가 생성 결과 원격 알림을 보내지 않았더라도, 새 프로젝트가 프로젝트 목록에 나타나면 앱은 그 프로젝트의
생성을 완료로 기록한다. 사용자는 곧바로 다른 저장소를 등록할 수 있다.

**주요 행위자**: 회원 사용자

**우선순위 이유**: 결과 알림이 누락되면 사용자는 새 프로젝트가 보이는데도 최대 1시간 동안 앱과 공유
확장 어디서도 새 저장소를 등록할 수 없다. 핵심 등록 흐름이 막히는 결함이다.

**독립 테스트**: 프로젝트 P의 진행 중 기록이 있는 상태에서 원격 알림 없이 P를 포함한 목록을 불러오고,
기록이 완료로 바뀌며 홈 잠금과 공유 확장 차단이 풀리는지 확인한다.

**수용 시나리오**:

1. **전제** P의 생성이 진행 중이고 결과 원격 알림이 오지 않았다, **실행** 앱이 포그라운드로 돌아와 P가
   포함된 목록을 받는다, **결과** P의 생성 기록이 완료가 되고 홈의 "지금 불러오기" 잠금이 풀린다.
2. **전제** 1과 같다, **실행** 사용자가 공유 확장에서 다른 저장소를 공유한다, **결과** 공유 확장이 생성
   중 안내로 막지 않고 등록을 진행한다.
3. **전제** P의 생성이 진행 중이다, **실행** 사용자가 목록을 당겨서 새로고침하거나 다음 페이지를 불러와 P가
   포함된 결과를 받는다, **결과** P의 생성 기록이 완료가 된다.

---

### 시나리오 2 - 생성 진행 화면이 목록 확인으로 완료 흐름으로 넘어감 (우선순위: P1)

생성 진행 화면에서 기다리는 동안 결과 알림 없이 목록에서 프로젝트가 확인되면, 진행 화면은 원격 알림으로
완료된 것과 같이 완료 흐름으로 넘어간다.

**주요 행위자**: 회원 사용자

**우선순위 이유**: 기록을 해제하면 잠금은 풀리지만 진행 화면은 결과를 받지 못해 계속 기다린다. 완료로
전이해야 진행 화면도 끝난다.

**독립 테스트**: 진행 화면이 P를 기다리는 상태에서 P가 포함된 목록 로드를 일으키고, 진행 화면이 완료
흐름으로 넘어가는지 확인한다.

**수용 시나리오**:

1. **전제** 사용자가 P의 생성 진행 화면에서 기다리고 있다, **실행** 목록 로드 결과에 P가 포함된다,
   **결과** 진행 화면이 원격 알림 `QUIZ_READY`를 받았을 때와 같은 완료 흐름으로 넘어간다.

---

### 시나리오 3 - 목록 확인과 원격 알림이 함께 와도 결과는 한 번 (우선순위: P2)

목록 확인으로 완료를 반영한 뒤 같은 프로젝트의 원격 알림이 늦게 도착하거나, 원격 알림으로 이미 결과가
반영된 뒤 목록이 로드되어도 기록과 화면은 한 번만 바뀐다.

**주요 행위자**: 회원 사용자, 연동 시스템(서버 원격 알림)

**우선순위 이유**: 두 결과 경로가 생기면서 중복 반영이나 결과 뒤집힘이 생길 수 있다.

**독립 테스트**: 목록 확인 뒤 같은 프로젝트의 `QUIZ_READY`·`QUIZ_REJECTED`를 주입하고, 반대 순서로도
주입해 기록 전이 횟수와 최종 상태를 확인한다.

**수용 시나리오**:

1. **전제** P를 목록 확인으로 완료했다, **실행** P의 `QUIZ_READY` 알림이 늦게 도착한다, **결과** 기록은
   완료 그대로이며 완료 시각이 바뀌지 않는다.
2. **전제** P를 원격 알림으로 이미 실패(`QUIZ_REJECTED`)로 기록했다, **실행** P가 포함된 목록을 받는다,
   **결과** 기록은 실패 그대로다.
3. **전제** P를 목록 확인으로 완료했다, **실행** 같은 목록 로드가 다시 일어난다, **결과** 기록과 화면은
   더 바뀌지 않는다.

---

### 시나리오 4 - 결과 경로 가정과 알림 방식 기록 갱신 (우선순위: P3)

개발자는 생성 결과가 원격 알림뿐 아니라 목록 확인으로도 들어온다는 사실과, 목록 경로의 사용자 알림
방식을 문서에서 확인할 수 있다.

**주요 행위자**: 개발자

**우선순위 이유**: 048은 "생성 결과는 원격 알림으로만 들어온다"는 가정으로 로컬 결과 알림을 제거했다.
새 결과 경로가 생겼는데 이 가정이 남으면 이후 명세가 잘못된 전제를 따른다.

**독립 테스트**: 048 명세의 해당 가정에 이 명세로 갱신되었다는 표시가 있는지 검토한다.

**수용 시나리오**:

1. **전제** 048 가정이 결과 입력을 원격 알림뿐이라고 적고 있다, **실행** 이 기능을 완료한다, **결과**
   048 가정에 목록 확인 경로가 추가되었고 알림 방식은 이 명세를 따른다는 표시가 있다.

### 예외·경계 사례

- 목록에 포함된 프로젝트라도 그 생성 기록이 이미 완료·실패이면 기록을 바꾸지 않는다.
- 생성 기록에 아직 프로젝트 식별자가 붙지 않은 요청(등록 응답 전)은 목록과 대조할 수 없으므로 바꾸지 않는다.
- 생성 기록에 없는 프로젝트가 목록에 있는 것은 정상이다. 목록의 다른 프로젝트는 기록을 만들거나 바꾸지 않는다.
- 불러오지 않은 페이지에 있는 프로젝트는 확인되지 않은 것으로 본다. 다음 페이지를 불러와 확인되면 그때 반영한다.
- 목록 로드가 실패하면 기록을 바꾸지 않는다(마지막 성공 목록을 다시 대조하지 않는다).
- 목록 확인으로 한 완료 반영은 목록 갱신 계기(046 FR-002의 결과 도착 알림)로 쓰지 않는다. 그렇게 하면
  목록 로드가 다시 목록 로드를 부르는 반복이 생긴다.
- 게스트이거나 로그인 전에는 목록을 불러오지 않으므로 이 규칙도 동작하지 않는다.
- 공유 확장은 목록을 불러오지 않는다. 공유 확장의 차단은 메인 앱이 반영한 공유 저장소 기록으로 풀린다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 서버 프로젝트 목록 로드(첫 페이지, 새로고침, 다음 페이지)가 성공하면, 받은 항목의
  프로젝트 식별자 중 진행 중 생성 기록의 프로젝트 식별자와 같은 것을 그 프로젝트의 생성 완료 결과로
  반영해야 한다.
- **FR-002**: 시스템은 FR-001의 완료를 원격 알림 `QUIZ_READY`로 인식한 완료와 같은 결과로 반영해야 한다.
  생성 기록은 완료가 되고, 생성 진행 화면·홈 잠금·공유 확장 차단이 원격 알림으로 완료된 경우와 같이
  결과를 따라야 한다.
- **FR-003**: 시스템은 FR-001로 반영한 완료 시각을 그 목록 로드가 성공한 시각으로 기록해야 한다.
- **FR-004**: 시스템은 이미 완료·실패인 생성 기록, 프로젝트 식별자가 없는 생성 기록, 생성 기록이 없는
  프로젝트에 대해서는 FR-001로 기록을 만들거나 바꾸지 않아야 한다.
- **FR-005**: 시스템은 같은 프로젝트의 결과가 목록 확인과 원격 알림으로 모두 들어와도 생성 기록 전이를 한
  번만 해야 하며, 먼저 반영된 결과를 뒤집지 않아야 한다.
- **FR-006**: 시스템은 FR-001로 반영한 완료를 목록 갱신 계기(046 FR-002)로 쓰지 않아야 한다.
- **FR-007**: 시스템은 FR-001로 완료를 반영할 때 로컬 알림이나 다른 사용자 알림을 추가로 보내지 않아야 한다.
- **FR-008**: 이 변경은 서버 API와 원격 알림 payload를 바꾸지 않아야 하며, 목록이나 생성 상태를 주기적으로
  조회하는 폴링과 새 목록 요청 계기를 추가하지 않아야 한다(046 FR-020, 048 FR-009 유지).
- **FR-009**: 시스템은 원격 알림 결과 반영, 결과 보존·재시도, 보관 기한 만료, 로그아웃 해제, 프로젝트 삭제
  시 기록 해제(046 FR-022)를 변경 전과 같이 유지해야 한다.
- **FR-010**: 개발자는 048 명세의 가정 "생성 결과는 원격 알림으로만 들어온다"에 목록 확인 경로가 추가되었고
  목록 경로의 알림 방식은 이 명세 FR-007을 따른다는 표시를 붙여야 한다. 048 본문의 다른 문장은 고쳐 쓰지 않는다.

### 핵심 엔터티

- **생성 기록**: 요청한 저장소, 등록 후 붙는 프로젝트 식별자, 진행 중·완료·실패 상태, 요청·완료 시각을
  담는 공유 저장소 기록이다(기존 엔터티, 변경 없음).
- **프로젝트 목록 항목**: 서버 목록 한 페이지의 항목이다. 이 기능은 항목의 프로젝트 식별자만 사용하며,
  항목에는 생성 상태 필드가 없다.
- **목록 확인 결과**: 목록 로드 성공 시 진행 중 기록과 대조해 얻은 "완료된 프로젝트 식별자와 확인 시각"이다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 결과 원격 알림 없이 진행 중 프로젝트가 포함된 목록을 받으면, 그 목록 로드 반영 즉시(보관
  기한을 기다리지 않고) 생성 기록이 완료가 되고 홈 잠금과 공유 확장 차단이 풀린다. 자동 테스트와 실기기에서
  100% 재현된다.
- **SC-002**: 생성 진행 화면에서 기다리는 중 목록 확인이 일어나면 진행 화면이 원격 알림 완료와 같은 완료
  흐름으로 넘어간다.
- **SC-003**: 완료·실패 기록, 식별자 없는 기록, 기록 없는 프로젝트가 섞인 목록을 받아도 해당 기록 변경이
  0건이다.
- **SC-004**: 목록 확인과 원격 알림을 어떤 순서로 주입해도 한 프로젝트의 기록 전이는 1회이고 최종 상태는
  먼저 반영된 결과와 같다.
- **SC-005**: 목록 확인으로 완료를 반영해도 추가 목록 요청이 0건이고, 로컬 알림 예약이 0건이다.
- **SC-006**: 기존 생성 결과 반영·중복 제거·만료·로그아웃·삭제 해제·목록 자동 갱신 자동 테스트가 변경 전후
  모두 통과한다.
- **SC-007**: 048 명세의 결과 경로 가정에 이 명세의 갱신 표시가 있다.

## 가정

- 서버 프로젝트 목록에는 문제 생성이 끝난 프로젝트만 나타난다(2026-10-01 사용자 확인). 생성 불가
  (`QUIZ_REJECTED`) 프로젝트는 목록에 나타나지 않는다고 본다. 이 가정이 틀리면 목록 포함을 완료 근거로 삼을
  수 없으므로 이 기능을 다시 정한다.
- 목록 로드는 앱이 포그라운드일 때만 일어난다(046 FR-001~FR-004). 그래서 목록 경로로 완료가 반영되는
  순간 사용자는 앱 화면을 보고 있으며, 잠금 해제와 진행 화면 전환으로 결과를 알 수 있다. 목록 경로에는 별도
  사용자 알림을 두지 않는다(FR-007). 이는 048 가정 "원격 알림이 아닌 결과 경로가 생기면 그때 알림 방식을
  다시 정한다"에 대한 결정이다.
- 새 프로젝트는 목록 첫 페이지에 나타난다고 본다(최신 등록 순). 첫 페이지에 없으면 다음 페이지를 불러올
  때 반영된다.
- 목록 확인 시각은 서버의 실제 생성 완료 시각보다 늦을 수 있다. 완료 시각은 보관 기한 계산에만 쓰이므로 이
  차이는 동작에 영향이 없다.
- 이 기능은 048(`feature/generation-outcome-payload`)의 로컬 결과 알림 제거와 payload 인식 위에서 동작하며,
  048 브랜치를 기준으로 한다.
