04

반복 구조 — List와 Stack

같아 보이는 반복이라도 개수를 데이터가 정하는가와 스크롤로 넘치는가에 따라 구현이 완전히 달라집니다. 이 둘을 섞으면 항목이 늘었을 때 화면 밖으로 밀리거나, 반대로 고정 개수에 불필요한 지연 로딩이 붙습니다.

List

개수를 데이터가 정하고, 넘치면 스크롤합니다. 항목마다 안정적인 id가 필요하고, 0개일 때 무엇을 보여줄지 반드시 정의해야 합니다.

LazyVStack(spacing: LayoutToken.gutter) { ForEach(projects) { ProjectRow($0) } } // 0개 → EmptyState
Stack

개수가 설계 시점에 정해지거나, 주어진 폭을 나눠 갖습니다. 스크롤하지 않으므로 빈 상태도, 지연 로딩도 필요 없습니다.

HStack(spacing: LayoutToken.tightSpacing) { ForEach(0..<total) { i in Segment(filled: i < done) .frame(maxWidth: .infinity) } }
ForEach가 있다고 List는 아닙니다 — ProgressSegments는 칸 수를 총 문제 수가 정하지만, 넘치지 않고 주어진 폭을 균등하게 나눠 갖습니다. 그래서 Stack입니다. 문제 수가 20개가 되면 칸이 좁아질 뿐 화면 밖으로 나가지 않아야 하므로, 각 칸에 고정 폭을 주지 않고 maxWidth: .infinity로 둡니다. 같은 이유로 요일 7칸과 차트 바 7개도 Stack입니다.

HScroll — 세 번째 분류

칩은 글자 길이만큼 폭을 요구해 균등 분할이 불가능하고, 정본에서 이미 콘텐츠 폭을 넘어 잘려 있습니다. 가로 스크롤 한 줄 · 단일 선택으로 확정합니다. 세로 리스트와 달리 스크롤 방향이 화면과 직각이므로, 좌우 여백을 컨테이너가 아니라 콘텐츠 인셋으로 줘야 첫·마지막 칩이 화면 가장자리에서 잘리지 않고 끝까지 스크롤됩니다.

ScrollView(.horizontal, showsIndicators: false) { HStack(spacing: LayoutToken.compactSpacing) { ForEach(filters) { Chip($0, isSelected: $0 == active) { … } } } .padding(.horizontal, LayoutToken.margin) // 컨테이너가 아니라 콘텐츠에 } .scrollClipDisabled() // 칩이 여백 밖까지 흘러가게 // 단일 선택 — 옵셔널이 아니라 값 하나를 들고 간다 @State private var active: SavedFilter = .all // 같은 칩을 다시 눌러도 해제되지 않는다: active = filter (토글 아님)
줄 수1줄 고정 — 줄바꿈 없음, 칩 라벨은 Body 2 1줄 고정 여백콘텐츠 인셋 margin (20) · 컨테이너는 화면 폭 전체 스크롤 표시숨김 — 정본에 스크롤바가 없음 선택 유지선택된 칩이 화면 밖이면 진입 시 보이도록 스크롤 선택 규칙단일 선택 · 항상 하나가 선택됨 — 해제 없음
