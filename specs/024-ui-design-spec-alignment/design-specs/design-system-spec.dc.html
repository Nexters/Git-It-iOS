01

정규화 규칙

아래 다섯 규칙을 이 문서 전체에 일관되게 적용했습니다. 규칙이 값을 바꾸는 경우는 없고, 이름과 소속 계층만 바꿉니다.

R1
원시 토큰과 역할 토큰을 분리한다
팔레트 위치(Grey600)는 ColorToken, 화면에서의 역할(CardBackground)은 SemanticColorToken. 컴포넌트는 역할 토큰만 참조하고, 원시 토큰 직접 참조는 상태색처럼 역할이 없는 경우로 제한한다.
R2
외부 라이브러리 잔여 변수는 토큰이 아니다
Figma Ungrouped 컬렉션 79개 중 Apple UI Kit·Material·SDS에서 유입된 변수는 제품 토큰에서 제외한다. 제품이 실제로 소비하는 25개(Variable collection)와 Liquid Glass·Home Indicator 계열 기기 상수만 남긴다.
R3
자동 생성 이름을 규격 이름으로 확정한다
Property 1=Default, Component 7처럼 의미가 없는 이름은 6장의 표에 따라 확정한다. 세트 이름이 그대로 SwiftUI 타입 이름, variant 축이 enum 이름, variant 값이 case 이름이 되도록 맞춘다.
R4
렌더링 값은 보존하고, 이름만 바꾼다
Figma에 있는 수치(18px 패딩, 25px gap, 0.5px 선)를 4·8의 배수로 스냅하지 않는다. 값이 예외적으로 보여도 그것이 현재 렌더링이므로 그대로 토큰화하거나 컴포넌트 로컬 상수로 둔다.
R5
한 곳에서만 쓰는 수치는 토큰이 아니다
두 컴포넌트 이상에서 같은 의미로 반복되는 값만 토큰으로 올린다. 한 곳에만 나오는 값은 컴포넌트가 소유하는 상수로 둔다. iOS 최소 터치 44pt에 못 미치는 표면 크기도 토큰이 아니라 컴포넌트 상수로 두고 터치 영역을 따로 확보한다.

6.3 파일 구조와 레이어 규칙

페이지를 역할로 나눈다 — 현재 한 페이지에 Design system·UI·SECTION이 섞여 있습니다. 01 Foundation(토큰·타이포), 02 Components(제품 컴포넌트 세트), 03 Screens(화면), _Mockup(Apple UI Kit 등 외부 자산)으로 분리합니다.
분류를 세트 이름에 드러낸다 — 세트 이름에 Controls/, CollectionItems/, Scaffolds/, Overlays/, Indicators/, Displays/ 접두를 붙여 Controls/ActionButton 형태로 씁니다. 이모지 접두(🧰/, 🌓)는 제거합니다.
레이어 이름을 파라미터 이름으로 — Wrap, Container, Frame 2147238328 대신 title, meta, progressSegments처럼 컴포넌트가 받을 값의 이름을 씁니다. 텍스트 레이어 이름이 곧 SwiftUI 프로퍼티 이름이 됩니다.
인스턴스 오버라이드를 쓰지 않는다 — 저장문제 카드의 버튼처럼 인스턴스에서 반경·패딩을 바꾸면 세트가 더 이상 규격이 아니게 됩니다. 변형이 필요하면 세트에 variant를 추가하고, 아니면 세트 값을 따릅니다.
중복 세트를 통합한다 — Chevron 계열 11개 단일 심볼(ChevronLeft1/2, Chevron left, Chevron.Left)은 SF Symbols로 대체하고, Bookmark 4개 세트는 Controls/BookmarkButton 하나로 합칩니다. Chip·Tag 세트 3개도 Controls/Chip과 Displays/TagBadge 둘로 정리합니다.
모든 색·간격·반경을 변수로 바인딩한다 — 다수의 레이어가 hex와 수치를 직접 물고 있습니다. 2장의 토큰을 Variable로 등록하고 레이어 fill·stroke·radius·간격을 변수 참조로 바꿔야 값 변경이 한 곳에서 끝나고, 구현 쪽 토큰과 이름이 1:1로 맞습니다.
